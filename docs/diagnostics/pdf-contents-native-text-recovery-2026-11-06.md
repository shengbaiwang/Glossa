# 扫描 PDF 损坏文字层的目录恢复（2026-11-06）

## 故障与依据

用户指定的 407 页扫描 PDF 有旧 PaperCapture 文字层。它不是可靠的电子正文：目录标题、行序和页码均有损坏。旧实现见到非空原生文字就跳过图像识别，目录证据侧存也写成 native 标记；反复重试仍复用同一损坏材料，因此拒绝发布完整目录。另有独立映射缺陷：章标题与第一节共用印刷页码时，`<=` 将相等页码误判为页码系统重启，清除了已校准的偏移。

实际材料还暴露出续页页眉混入目录、跨行长标题、孤立页码、字号误推层级及图表目录边界。一次 OCR 的破折号也可能误识别为汉字“一”；不能靠拼接多次识别或损坏文字层相互印证来发布标题。

## 修复边界

- 目录／标题证据允许独立读取图像，即使 PDF 自带非空文字。目录证据升级为 `vision-contents-2`，旧 native／旧识别版本自动重建；普通阅读 OCR、选区顺序、CFI 与旧批注侧存不替换。
- 目录使用三个有界精确分辨率，按行框重建标题与页码，保留未覆盖行。候选替代标题必须来自同一来源行及同一印刷页码，最多两个；出现歧义时优先完整单次读取，并经独立正文图像精确核验，不引入中文近形字替换。
- 相同印刷页码保留校准；只有递减或编号系统变化才另建映射。正文内部标题及独立页码证明用于校准，边缘页眉不能成为重定位依据。
- 续页页眉须有其他页面的重复位置／变动页码证据才排除；跨行和孤立页码须有几何依据才连接。中文章／节优先使用明确结构，前后附属材料保持顶层；图表目录独立停止。
- 提取器升级为 `pdf-contents-13`。检查点仍绑定完整指纹、修订、源页证据和结构；所有目录项通过目标核验才发布，失败保留原有导航。没有针对本书名称或固定页码的产品分支。

## 验证

真实材料在 Git 忽略的 `.glossa-dev/qa/pdf-contents-20261106/` 中隔离运行，未改原 PDF。人工查看三页目录、49 个不同目标页及对应印刷页码，核对 56 项（15 个顶层、41 个子项）标题、目标及父子关系；只容许标点和空白归一化，不替换汉字。经核对的预期清单与完整源码／助手指纹随评测记录保存，书名、正文、截图和预期标题不提交。
