# 封面持续显示修复

日期：2026-11-06（Asia/Singapore）。前次调查见 [设置与封面异常](library-cover-settings-2026-11-05.md)。

用户补充：鼠标不在页面时封面不显示，要求长期稳定修复。日常应用现场检查中，首次截图为整架文字后备，点击顶栏空白后图片封面出现，后续截图又回到文字后备；尚未由该现象单独区分鼠标位置、窗口焦点和后台绘制。

## 可重复缺陷与修复

- 旧实现将图片设为 `invisible`，只在 Next Image 转发 `onLoad` 后显示。实际 Next 实现先等待 `img.decode()`；将这一步的 Promise 保持等待时，真实浏览器图片已完成加载且尺寸有效，封面仍不可见。
- Next Image 的内部 ref 依赖 `onError`，挂载 ref 会执行 `img.src = img.src`；封面每次渲染生成新的错误回调。真实浏览器回归确认普通进度更新会重复写入成功图片的同一 `src`。这两项缺陷可确定复现，但不称为生产现场全部现象的唯一根因。
- 改用原生 `<img>`，挂载即加载，使用原生 load 和有效尺寸确认成功；不调用额外 decode Promise，不隐藏加载中的图片，也不因进度或鼠标事件重写图片地址。书架仍按原有虚拟列表限制挂载范围，不预先加载整库。
- 纸色后备位于图片下层。替换请求先挂载在旧成功图下方，加载成功后才移除旧图；原图比例、透明封面的纸色背景、版本失效、签名 URL、一次自动重试及明确刷新恢复保持。
- ref 检查处理 hydration 前已经成功或失败的缓存图；同一次请求只发布一次有效尺寸／失败，避免缓存检查和随后事件重复通知。
- 后续复核发现并修复父卡片的缓存时序问题：子封面 ref 先发布有效比例，`BookItem`／`GroupItem` 的重置 effect 随后将其清空，会使完整封面失去原比例居中。比例状态现绑定书籍、有效封面 URL 和封面版本，不再依赖父子 effect 的执行顺序。
