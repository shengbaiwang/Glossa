# NotebookLM 引用交互与 Glossa 的落地

日期：2026-09-22。依据公开官方文档与本地源码核对；未登录竞品账号实测，未推测其内部检索或生成实现。

## 参考依据

Google 的[对话帮助](https://support.google.com/notebooklm/answer/16179559?hl=en)明确描述：引用可用于核对回答；悬停可读完整引文，点击可回到引文及其上下文；使用者可以选择回答所依据的来源。原 NotebookLM 帮助链接目前重定向至 Gemini Notebook 帮助。本文沿用用户使用的 NotebookLM 名称。

值得借鉴的是低成本的核对路径：先在回答旁快速看依据，需要更多上下文时再进入原文。引用的存在便于检查，并不保证模型的理解正确。未把公开产品交互当作其底层算法的证据。

## 与 Glossa 的对应关系

| 参考交互 | Glossa 中的选择 | 保留的约束 |
| --- | --- | --- |
| 答案内引用 | 来源按该回答首次出现顺序编号；重复来源沿用编号；正文含义保持可读 | 编号由本地 UI 生成，模型仍只能提供已发送的 sourceId |
| 悬停看引文 | 鼠标悬停或键盘聚焦打开原文预览，显示所附范围记录的章节及本机引文 | 不翻页、不调用模型、不提取邻段；读取仍只核验该来源锚点 |
| 点击查看上下文 | 点击后再次本机核验，再沿既有阅读器跳转，并临时标出精确原文 | 无法核验时保留明确未核验的快照，禁止跳转；不保存为笔记或原生选区 |
| 连续核对依据 | 同一回答实际引用的来源可前后查看，带当前位置/总数；保留首次跳转前的阅读位置 | 不把全部候选证据当作已被答案引用的来源，不扩大附件 |
| 选择来源 | 延续主动引用当前页、选区或明确阅读段的固定会话快照 | 普通聊天只带书籍元数据；翻页不更新附件；旧版本保留各自依据 |

Glossa 是阅读器，因此正文区域承担查看完整上下文的职责，不再增加全书来源管理区。短暂预览负责快速核对，底部原文区负责停留阅读与连续切换，返回按钮保持阅读闭环。导图继续沿用没有行内来源编号的节点交互；仅共用临时原文高亮和既有来源面板。

## 本轮实现与验收范围

- 提示模型把引用贴在对应论断后，优先直接支持该论断的文段；不能用一组松散相关引用替代逐处依据。实际语义是否成立仍需读者判断。
- 原文预览通过本地解析与锚点核验取得；加载、失败、关闭、快速切换、迟到结果和版本变化均有明确生命周期。失效引文不显示成功身份。
- 临时高亮使用 CSS Highlight，不改变书籍文字节点、原生选区、批注或同步数据；翻页、关闭原文、切换引用及返回时清理。不支持该 API 的引擎仍可查看核验后的原文面板。
- 保留 `conversation-3` 和每回答版本的阅读快照，不迁移数据库。未新增依赖、向量库、联网/全书工具、开放 Agent 或自动笔记功能。
- 以原创合成 EPUB、模拟服务、真实 Chromium 测试核对范围隔离、预览、跳转、准确高亮、多引用、返回与主题布局；单元覆盖不可信标签、编号、取消、核验失败及兼容回退。测试结果记录于 `PROGRESS.md`。

真实模型的逐句引用覆盖率、引用是否足以支撑解释、长段落检索效果，以及原生 WebKit 实际体验仍需日常阅读评估，不能以 UI 和模拟服务测试替代。
