# 对话与 Cherry Studio 的差距盘点

日期：2026-09-12。依据当前工作区源码（含已有未提交改动）及 Cherry Studio 当日官方文档。属于产品咨询，不改变 PLAN 的已授权范围；未运行 Cherry Studio、调用真实模型或核验安装版是否包含当前源码。

## 当前已具备

Glossa 已有流式 Markdown、停止保留部分回答、失败重试、最后回答重新生成、复制、跨模型续聊、模型列表搜索/手输、连接测试、本机按书会话、独立草稿、自建提示词。滚动已尊重用户上翻，提供返回最新回答。历史加载失败防覆盖、保存失败重试及迟到请求隔离已有实现，不能把这些列为缺失。

代码依据：`ConversationPanel.tsx`、`ConversationModelPicker.tsx`、`ModelSettingsPanel.tsx`、`conversation/generate.ts`、`conversation/schema.ts`、`conversation/prompts.ts`、`ai/provider.ts`，均位于 `apps/readest-app/src/glossa/`。

## 值得借鉴的差距与优先级

| 优先级 | 本地代码事实 | 建议与阅读价值 |
| --- | --- | --- |
| 第一批 | 消息只能复制回答、重生成最后一轮；重生成成功替换原轮。没有问题编辑、单轮删除、回答版本与分支入口。 | 先支持编辑最后问题后重发、保留重生成版本，降低纠错成本；任意历史分支可后置。删除或编辑历史必须定义后续消息处理，不能留下虚假的连续性。 |
| 第一批 | ProviderConfig 只有服务身份、地址和模型；统一发送 chat/completions、stream=true、max_tokens。已对官方 GLM-5.3/Flash 特判 reasoning_effort=low，未开放参数。只消费 content，不保留 reasoning/usage。 | 先核验常用服务的参数兼容性，提供受能力约束的推理强度与输出上限；不支持时省略字段。无需堆服务商数量，也不应允许任意参数覆盖模型身份。 |
| 第一批 | 输入框及生成、存储协议均限制问题为 2,000 字符；输入框自动增高至 180px。 | 提供临时展开编辑及适度提高用户主动输入上限，需要同步协议校验。此建议不等于恢复自动正文提取或附件系统。 |
| 第二批 | 历史以首问前 48 字符作为下拉标签；无命名、搜索、归档入口，每书 20 会话、每会话 40 轮。 | 先补会话重命名和本书历史搜索，再按真实使用考虑归档与容量策略。无需跨书知识检索。 |
| 第二批 | ReactMarkdown + remarkGfm 已支持基础排版、表格与代码；没有数学渲染插件、代码专属操作，回答字号固定为 14px。 | 优先数学公式、侧栏字号及代码块复制。保留禁止原始 HTML 执行与远程图片自动请求。 |
| 第二批 | 自建提示词选择是全局状态，历史保存 provider 与元数据但不保存所用提示词内容/版本。 | 可考虑会话记住选择，消息详情记录发送时提示词快照，帮助复现差异。属于待决定的设置语义变更，不恢复内置预设。 |
| 后续 | 已有 401/403、429、404 等错误提示，但部分通用提示还写“章节/笔记”；未记录每轮 token 或延迟。 | 先修正语境，再提供折叠的调用详情，记录服务实际返回的用量与首字/总耗时；无数据不虚构，成本与账单区分，不新增遥测。 |

第一批内部先后应按真实痛点确定：若主要是不便纠错，先消息操作；若主要是连接失败或等待久，先服务兼容与诊断。当前没有实测证明请求参数是回答质量问题的根因。

## Cherry Studio 的可核验参照

- [对话与助手](https://docs.cherryai.com.cn/cherry-studio/preview/chat)：支持助手级模型参数、推理强度控制、展开输入、公式与显示设置。Glossa 借鉴必要控制与设置复用，不照搬助手市场。
- [多模型比较与分支](https://docs.cherryai.com.cn/advanced-basic/chat/model-compare-branches)：可从消息建立独立路线并保留此前对话。对 Glossa 的启发是保留可比较的回答和纠错路径；本文没有据此声称已核验 Cherry 的每一种消息编辑动作。
- [项目简介](https://docs.cherryai.com.cn/)：明确列出历史搜索、导出、多协议服务接入及备份。Glossa 本机对话未接入阅读云同步；备份与迁移可作为后续价值，导出及同步新增范围须另行决定。
- [长对话与队列](https://docs.cherryai.com.cn/advanced-basic/chat/context-queue)：包含历史窗口、压缩、可选重试与队列。Glossa 当前 12 轮/48,000 字符有界完整消息是主动范围选择，不建议借盘点恢复摘要、无限历史或自动队列。
- [用量统计](https://docs.cherryai.com.cn/pre-basic/settings/usage)：提供调用统计及估算费用。Glossa 可借鉴必要的请求诊断，不需要建设整套使用仪表盘。

## 不应计为当前不足

知识库/RAG、自动附加书籍正文、联网搜索、MCP/Agent、助手市场、画图、HTML 小程序、多模型并排工作台与完整笔记系统均不属于当前简单对话的必补项。自建提示词已是合适的轻量形式。简单对话仅自动附带书名、作者、目录层级；导读/导图另行承担基于原文的核验与跳转。

## 回答质量需要独立验证

Cherry 功能丰富不能证明同一模型在那里更准确。既有 GLM 评测属于已经删除的内置提示词实验，不能当作现行无默认 system 的质量结果。建议将相同服务地址、模型、system、元数据、普通历史、问题、推理及输出参数对齐，禁用 Cherry 额外检索/工具，以少量固定题重复对照解释有效性、事实错误、追问一致性及延迟。缺少这些证据时，不把问题归因于 UI、提示词长度或客户端名称。

本轮仅源码与公开文档检查，未改产品、读取密钥/用户书籍或运行模型。文档无需产品测试；检查文档差异与本地引用文件存在性。
