# 阅读 harness：案例与投入判断

实施状态：用户随后采纳方向，首版已按 [阅读 harness 设计](../design/reading-harness.md) 实施；本文保留决策前的案例依据与评估建议。

日期：2026-09-21。状态：研究建议，未批准实施，不替换 PLAN.md 或当前简单对话边界。调研使用公开的一手文档与本仓库源码；未运行竞品、真实模型评测或用户实验。

## 判断

值得验证一个内嵌于 Glossa 的轻量阅读 harness：为模型提供有边界的文本读取、检索、来源记录和少量补查机会。暂不值得独立建设通用 agent 平台、工具市场、多 agent 调度或任意代码执行环境。

这里 harness 指模型之外的执行层：保存本轮讨论对象和授权范围，执行工具，限制调用次数与正文量，记录来源，处理取消与错误，验证引用身份。它可以先使用确定性流程，再视评测结果增加模型自主选择工具的能力。

价值假设是减少读者复制、寻找和重新说明原文的操作，并提高针对具体版本的回答质量。工具数量、回答长度和 agent 调用次数不作为成功指标。案例只能证明能力存在，不能证明 Glossa 的留存、付费意愿或阅读理解收益。

## 已核对的 Glossa 基础

- `apps/readest-app/src/glossa/conversation/generate.ts:48`：新对话自动材料只有书名、作者和章节标题字段（UI 提供目录路径），随后附有界的当前版本普通聊天消息。正文及旧材料不会因为扩展对象而意外进入请求。
- `apps/readest-app/src/glossa/ai/provider.ts`：现有 provider 支持普通 system/user/assistant 文本和流式文本响应；没有工具调用消息、工具结果或工具调用增量的完整协议。兼容 API 地址不等于模型能可靠使用工具，需要单独验证能力并保留普通对话降级。
- `apps/readest-app/src/glossa/context/chapters.ts` 与 `passages/passages.ts`：已有章节边界、完整文本块和阅读段拆分；现行导图阅读段有 20,000 字符、200 个来源上限。这些是复用基础，不代表适合作为新对话预算。
- `apps/readest-app/src/glossa/citations/sources.ts:12`、`:28`：已有来源 ID 白名单、CFI 与本机文本核验、文本恢复；`citations/navigation.ts` 提供导航接线。它们证明文本和位置可以核对，不能证明某句结论由该文本支持。

## 案例

### Readwise Reader / Global Ghostreader：最接近的产品参考

官方文档描述了全库搜索、段落引用预览与原文跳转、单文档侧栏对话，以及可编辑的自然语言 skills。读取工具和修改工具分组：前者默认允许，后者默认每次确认。已有创建高亮、编辑批注等写操作。

可借鉴：原文与对话并排；搜索后读取相关段落；引用可回到具体位置；读写能力分离。其全库范围不应直接照搬为 Glossa 默认权限。此案例说明“阅读器＋工具调用”已有直接竞争，不能单靠 harness 这一技术名词形成差异。

来源：[Global Ghostreader](https://docs.readwise.io/reader/guides/ghostreader/global)、[Ghostreader overview](https://docs.readwise.io/reader/guides/ghostreader/overview)。

### NotebookLM（当前官方页面称 Gemini Notebook）：来源体验参考

官方帮助支持选择本次来源、悬停查看引文、点击跳到原文、保存含引用的回答。当前页面还列出网页搜索、代码执行和文件生成等实验性 agent 能力；不应仍将它描述成只有静态文档问答。

可借鉴：来源可控制、回答可核对。其产品能力并不证明日常 EPUB 阅读需要代码执行或文件生成。Glossa 更值得检验的方向是阅读位置、指定范围和本机版本锚点的结合。

来源：[Use chat in Gemini Notebook](https://support.google.com/gemininotebook/answer/16179559?hl=en)。

### PaperQA2：可以查看实现的检索 agent

官方仓库将流程分为检索论文、收集与排序证据、生成带引用回答；agent 可修改查询并重复调用工具。项目重点是科学文献，包含向量检索、上下文摘要与重排，也提供不使用 agent 的调用方式。

可借鉴：把“找材料”“读材料”“回答”分开，证据不足时允许补查。它对科学文献的设计与评测不能直接外推到中文 EPUB、古籍注释或防剧透阅读；其 Python 技术栈及索引管线不适合不经验证整体接入现有桌面应用。

来源：[Future-House/paper-qa](https://github.com/Future-House/paper-qa)。

### Anthropic 工程经验：控制复杂度与检验工具

其工程文章区分固定工作流与模型自主决策的 agent，建议先用最简单的有效方案，并衡量额外延迟和成本。工具设计文章主张少量针对高价值任务的工具、精简且有意义的返回值，以及任务成功率、耗时、调用次数和 token 消耗等评测。

来源：[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)、[Writing effective tools](https://www.anthropic.com/engineering/writing-tools-for-agents)。前者最初发表于 2024 年，本文只借鉴架构原则，不据此判断当前 SDK 优劣。

## 建议的最小能力

先把“选中文段 → 连同必要且已获准的上下文回答 → 点击依据回原文”做成可对照的基线。随后仅在证据不足或跨段问题上试验有限补查。

| 工具草案 | 解决的阅读问题 | 返回边界 |
| --- | --- | --- |
| `read_passage` | “这里的这句话是什么意思？”；读取搜索命中的上下文 | 完整有界文本块、章节路径、宿主生成的 sourceId；锚点由本机保管 |
| `search_book` | “前面哪里定义过这个概念？” | 仅授权区间的命中片段；明确命中上限与搜索覆盖范围 |
| `get_outline` | 确定章节关系、选择需要补查的位置 | 按权限裁剪的目录结构；目录标题也可能剧透 |

选区与讨论焦点由宿主直接提供，可避免一次无必要的工具调用。跳转由用户点击引用触发，不让模型在回答途中移动阅读页。来源核验是宿主必经步骤，不依赖模型决定是否调用“验证工具”。

首次试验可把总工具调用数限制为 3 次，并设置独立的正文预算、超时及取消；该数字是实验起点，不是经验定律。达到上限应明确证据不足或请求扩大范围，不无限重试。不必把所有回答包成复杂 JSON：普通解释保留自然流式文本，来源关联使用可验证协议。

模型能选择在授权范围内查什么，不能自行扩大范围。当前阅读位置不等于前面全部读过；没有可信已读记录时，使用用户明确指定的章节/截止范围，不能把进度百分比称为已读权限。限制须在工具执行与返回正文前实现，不能只写进提示词。来源身份核验和“引文是否支持观点”分别评估。

后续有真实需要再添加个人笔记检索、比较两个授权文段，或将回答写入现有笔记/导图。网络查询适合考据、术语与背景问题，但应独立授权并区分外部来源；它不保证书中观点正确。代码执行只在公式、数据或可运行示例成为常见问题后考虑。

先在应用内部使用清晰的工具接口即可；MCP 可在确实需要其他客户端使用 Glossa 阅读能力时再评估。首轮不需要独立服务器、向量数据库、多 agent、自动摘要记忆或全书上传。

## 如何判断投入是否继续

建议用两周真实阅读积累约 30 个问题，固定模型和回答风格，对照三组：

1. A：现有元数据对话。
2. B：选区/授权局部正文＋固定检索流程＋单次回答。
3. C：与 B 相同权限、索引和正文预算，额外允许有限次自主搜索与读取。

按问题类型分别比较：局部解释、省略式追问、前文定义定位、跨段论证比较、缺证据/未授权/歧义。另用少量人工选定的正确证据检查模型本身是否能答对，避免把理解错误全归因于检索。

记录：关键证据召回、回答是否答中、引用实际支持与否、跳转成功、越界读取、首个有用回答延迟、总时间/费用，以及读者是否仍需手动找文或切换应用。只保存必要的本机评测记录，不建立遥测。保留未参与调参的问题；模拟工具测试不能替代真实模型试用。

建议的继续门槛：C 在需要检索的问题上，相比 B 明显减少手动找材料并提高正确回答比例，且实际等待可接受；例如预先约定提升至少 20 个百分点，并查看逐题结果。小样本阈值仅用于个人决策，不能宣称总体准确率；来源伪造与越界读取一旦出现，应先修复再扩大试用。

若 B 已解决大部分问题，保留轻量阅读层即可；若 C 只增加调用、延迟和长回答，停止扩展 agent。若真实需求持续集中在跨段查证，才值得逐步加强检索、有限工具规划及更可靠的引用关联。

## 产品方向与执行状态

个人使用价值值得验证；独立商业机会尚无证据。可检验的差异是本机 EPUB 的具体版本、阅读位置与范围、中文长文本体验，以及问完后迅速回到原文。Readwise 等已有相似工具能力，这些差异也必须通过真实使用证明。

本轮只完成研究与源码核对，未改动对话行为、PLAN.md、AGENTS.md 或用户数据，未恢复已移除 AI 功能。下一步候选是建立问题集和 B 组的最小验证规格；新正文读取与工具权限属于后续需要明确采纳的产品范围。
