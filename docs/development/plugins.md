# Glossa 插件开发草案（API 1）

设置中的一级「插件」菜单统一管理内置插件。当前仅加载随应用审核、构建的对话、导图、PDF 自动目录与网页导入；第三方区域预留在同一页，尚未开放安装。下面是供后续开发讨论和源码贡献使用的元数据契约，不是可安装包格式，也不承诺兼容 Obsidian API。

## 清单

实现位于 `apps/readest-app/src/glossa/plugins/manifest.ts`，内置清单也经过相同的 Zod 校验。[完整示例](plugin-example/manifest.json) 可以直接交给 `pluginManifestSchema.parse(unknown)` 校验。解析只返回元数据，不改变加载白名单、启用状态或权限。

| 字段 | API 1 草案约定 |
| --- | --- |
| `id` | 1–120 字符，字母开头，字母数字及点／连字符分段；内置 ID 保持兼容，第三方建议使用 `org.example.outline` 等命名空间 |
| `name` | 非空显示名称，最多 80 字符 |
| `author` | 非空作者名称，最多 120 字符 |
| `version` | 语义版本，如 `0.1.0`，允许预发布及构建元数据；不接受 `v1.0.0`、`1` 或首尾空白 |
| `apiVersion` | 必须为 `1`；与应用版本分开演进，不接受未知版本 |
| `activation` | `reader-panel`（用户打开面板）、`persistent-import`（持久导入／主动重导入）或 `library-import`（主动网页导入／系统分享），同时支持上述值的非空数组；保留旧单值兼容 |
| `format` | `EPUB`、`PDF`、`WEB`、`MD`，或这些值的非空数组；兼容旧单值清单，仅描述实际支持的格式。对话支持 EPUB／MD，导图仍仅 EPUB |
| `capabilities` | 最多四项：`reading-harness`、`model-provider`、`verified-sources`、`local-pdf-contents`、`web-page-capture` |

未知字段会被拒绝；没有 `main`、远程 URL 或可执行路径字段。能力列表描述可信源码的依赖，不是向外部代码发放的权限，也不构成安全沙箱。开关仍只接受内置已知 ID；外部清单不能通过设置字段加入加载表。草案改变时须同步示例、内置清单及契约测试，破坏兼容性的变更提升 API 版本。

## 当前源码贡献路径

1. 在 `glossa/plugins/registry.ts` 通过 `defineBundledPlugin` 声明元数据，并在 `loaders.ts` 增加固定的动态导入；任务入口与 `pluginPanelLoaders` 的面板入口分开白名单。保持 `PluginId`、宿主入口与设置同步的已知 ID 一致；不能把用户清单路径直接传给 `import()`。面板按格式筛选；双触发插件显式声明数组，打开面板不能隐式启动生成。
2. 阅读面板接入现有面板宿主；非面板任务复用 `runPluginTask`，由核心传入必要上下文。不要在导入元数据、打开设置、启用插件或翻页时调用模型或开始生成。
3. 请求、监听、计时器与自有句柄必须有清理路径。停用立即中止活动任务，任何异步加载后再次检查取消；重新启用不能复活旧 signal 或自动继续检查点。持久化历史、个人编辑、原始依据及 OCR 保留。
4. 模型、密钥、原书访问、来源核验、保存与同步继续走既有核心服务。清单中的能力不能绕过引用关闭、来源白名单或预算；阅读、选文、批注与笔记不应依赖插件启用。
5. 用原创材料和隔离存储验证按需加载、停用取消、迟到结果、保存失败、重开历史与设置导航。更新设计及进度中的真实验收边界。

当前 `defineBundledPlugin` 只供可信源码构建使用，不是外部注册 API。新增内置插件需代码审查及应用重建。

## 网页导入

`webImport` 声明 `library-import`／`WEB`，不进入阅读器右侧标签。仅主动网页导入和系统分享／深链接触发 `importWebPage`，抓取与转换按需加载；保存复用核心导入服务。菜单、分享入口及活动任务统一接受 `officialModules.webImport` 的显式布尔补丁。停用取消等待和图片下载，现有原生捕获在其有界操作返回后检查取消，不启动后续转换或保存；已开始的必要保存可以完成。重新启用不复用旧 signal，不消费停用时尚未接收的 iOS 分享队列。已有书籍不依赖插件，第三方清单也不能因此获得网页或文件权限。

## 后续第三方执行环境

独立菜单和统一清单为未来第三方插件提供接入位置。开放安装前仍需明确包验证、宿主能力接口、隔离执行、逐能力授权、故障卸载、版本升级与插件数据归属；第三方安装后的默认状态和授权流程届时另行设计，不能沿用内置插件的缺省启用规则。未来允许安装也不意味着自动读取原书、获得密钥或恢复历史任务。本轮没有实现这些执行能力。
