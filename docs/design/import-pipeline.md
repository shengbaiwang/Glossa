# 导入管线与书库持久化重构方案

日期：2026-10-28。用户已授权实施。下述完整架构按阶段落地；本节区分当前实现和长期目标，后文保留完整设计，不能将所有目标视为已实现。

## 本轮实现边界

- 页面固定四本切片已移除。共享服务连续补位，8ms 窗口只合并已经准备好的记录；每个输入在持久提交及清理后单独回调，最终结果数组仍按输入顺序。界面显示完成数、当前文件及阶段，不伪造字节百分比。
- 完整指纹后可直接复用已有且可用的托管记录，跳过格式解析与封面工作；提交重查最新身份和删除状态，不可复用时回到完整准备路径。同一 JS 运行环境的共享准入上限为 4 个活动导入及合计 256 MiB 的源文件大小估算，未知大小或超大文件独占；这不是硬内存上限，独立 WebView 各有自己的准入器。
- PDF 导入轻探测验证解析器、首页和元数据，跳过完整目录、页码标签和全页导航构建；真实封面仍在导入阶段生成。导入文档先释放，自动目录排队只持有描述信息，任务实际开始后重新打开。
- Native／Node 通过 `LibraryRepository` 将变化书目绑定参数写入单条原子 SQL。首次迁移书目与版本标记同时提交，保留旧 JSON；切换后数据库是唯一权威，故障拒绝回退旧快照。数据库与迁移快照绑定确定目录；数据库后端的数据目录搬迁暂时阻止原先的活动文件裸复制／删源流程，不能把关闭本地连接当作跨窗口停写保证。Web 暂留 JSON 后端，未声称已完成 WASM／OPFS 切换。
- 当前提交仍读取完整书目快照并建立内存指纹索引，SQL 指纹索引尚未用于直接候选查询。文件操作与数据库不在同一原子事务中；独立持久任务认领、发布日志／回执和自动崩溃收尾尚未实现。失败重试沿用完整身份与已有配置保护，不宣称具备全阶段崩溃恢复。
- 延期封面／非必要元数据、字段补丁全面迁移、阅读优先的统一 CPU／I/O 调度仍为后续目标。测试与各平台边界见 `PROGRESS.md`，不承诺未经实测的速度倍数。

## 目标与取舍

把导入从书库页面的循环中抽出，建立独立、有界、可恢复的任务管线；把书库更新从整份 JSON 回写收敛为按书籍／字段提交的事务。保留阅读引擎、格式解析器、原生流式 I/O、现有书籍 ID、文件位置、侧存、插件权限和完整身份核验。

主要优化目标是首本可用时间、慢文件对其他书的影响、重复导入成本和资源峰值。总吞吐以隔离基准验证，不预先承诺倍数。不通过放松完整指纹、源文件变化检查或目录核验换取速度。

## 一条管线、四个明确边界

```text
文件／文件夹／拖放／网页／分享／OPDS／自动扫描
                         ↓
               ImportCoordinator：任务及进度
                         ↓
 完整身份核验 → 已存在快速返回／新书暂存 → 最小格式验证
                         ↓
              LibraryRepository：事务提交
                         ↓
                书架发布，书籍可以打开
                         ↓
     有界补全队列：封面、非必要元数据、PDF 自动目录
```

备份恢复、同步下载登记、阅读进度、改名、分组、删除／恢复也通过同一个 `LibraryRepository` 写入。它们保留各自业务语义，不被强行变成普通文件导入。`DocumentLoader` 继续负责阅读；导入探测不再为所有格式创建完整阅读对象。

### 1. ImportCoordinator：连续处理，独立于页面

- 页面只提交请求、订阅事件、取消和重试；删除页面中的固定切片循环。单本与批量 API 成为同一协调器的兼容包装，不保留两套实现。
- 每本一个状态机：等待 → 核验 → 暂存／探测 → 待提交 → 已入库／已存在／失败／取消。不同阶段有不同资源预算，完成一个就补下一个，不等待同批最慢文件。
- 分开限制磁盘 I/O、解析器数量、估算内存及暂存字节；积压达到上限停止接收下一项。大文件不能耗尽全部解析预算，也不能被小文件永久饿死。初始限制取保守值，再以实际测试调整，不把新的固定数字当架构。
- 同一进程按书库复用协调器；跨窗口／进程以持久任务认领、代际和事务身份约束防止重复执行，不能仅靠模块级 Promise 队列。失去执行窗口的任务标记为中断，由用户主动继续，恢复前重新核验材料。
- 进度事件携带任务、尝试代际、单调序号及阶段。界面显示正在处理的文件、阶段和新增／已存在／失败数量；字节进度只用于可测的读取阶段，不伪造解析百分比。已入库数量仅在持久提交后增加。

### 2. SourceIO 与格式探测：先确认身份，再做昂贵工作

- 先计算完整内容身份并查询索引。已有且文件可用的记录直接复用，不再解包、渲染封面或重建配置；缺失文件恢复、主动 PDF 目录重试作为独立分支保留。
- 新书沿用原生流式复制并同步校验，将后续解析绑定到核验后的固定暂存文件。保留现有「完整指纹＋复制时再次核验」的保证；不能以修改时间／大小代替第二次内容核验，也不宣称所有来源都只读一遍。
- 原位读取继续完整复核源文件；无法保证稳定的来源保持保守路径。网页／浏览器使用有界流或 Blob，不能重新引入整本 ArrayBuffer 或逐块 IPC。
- `probeImport` 只完成格式有效性、打开阅读所需字段和必要转换。EPUB／MOBI 复用现有元数据快速路径并拆开封面解码；PDF 不再为了入库提前生成全目录与首页封面。必要结构损坏仍报导入失败，不能用只有文件名的占位记录假装可读。
- TXT 转换必须在可读提交前完成，源文件／阅读文件双指纹保留；Markdown 正文与已授权资源快照一起形成身份。不同内容不按书名、作者或格式合并。
- 有些格式仍需较重解析才能判定可读，允许专用适配器保留该成本；失败、取消和资源释放遵守统一契约。

### 3. LibraryRepository：唯一写入边界，逐条事务

- 目标是以专用书库数据库保存书目、身份索引、字段修订、导入任务／提交回执；原书和现有笔记、目录等侧存不在本轮整体搬迁。复用项目已有 Native／Node／Web 数据库适配层，不把可重建的搜索索引提升为权威书库。
- 当前 `DatabaseService` 的字符串 `batch` 不等于已经满足要求。先补齐绑定参数、同一连接内的原子命令、并发冲突及崩溃恢复契约；原生事务不得由可被其他请求插入的多次 IPC BEGIN／COMMIT 拼成。各平台独立通过契约后才切换。
- 使用按字段补丁与修订比较：导入只增加身份、初始分组和必要元数据，不能覆盖较新的个人改名、阅读进度、笔记或删除代际。旧整份 `saveLibraryBooks` 调用必须迁走，不能在新存储旁继续写旧快照。
- 书籍原 ID 为主键；完整指纹单独索引。新导入通过身份认领事务选定可复用记录。不能直接给全部历史书目加指纹唯一约束，因为历史重复、已归档记录及同步个人记录仍必须保留。
- 提交器只接收准备完成的记录，可立即提交或按很短的时间窗口合并已经就绪的记录；不等未完成的第 N 本。单次事务大小有上限，全部大型读取、解析、封面操作移出事务。
- 数据库提交后发布带修订号的变更事件，书架和其他窗口增量刷新；允许通过版本检查补读丢失通知。通知不是事实来源。

文件系统与数据库不能假装处于同一个原子事务。采用持久操作记录：核验暂存 → 记录发布意图及目标代际 → 将本任务拥有的文件发布到最终位置 → 事务核对最新身份／个人字段／删除状态并登记书目、回执和后续任务 → 通知界面。中途退出由日志核对已发布文件后完成或清理，只操作本任务拥有的文件；已有个人侧存绝不因重试覆盖。只有登记成功的书目可见。

### 4. 补全队列：排队时只保留轻量任务

- 入库不等待封面和非必要元数据；暂时显示原文件名及现有素纸封面。后台补全只写允许补全的字段，用户已经改过的字段优先。
- PDF 自动目录、封面等队列只保存书籍 ID、内容指纹、代际和选项，轮到执行才打开解析器；排队期间不持有整本 `BookDoc`。可以接受重新打开的少量成本，换取可控内存。
- 阅读交互优先，导入其次，自动补全最后；资源紧张时停止启动新的后台任务，当前任务在安全点收尾或让出。避免只改一个队列而让封面、OCR、同步上传同时抢占全部资源。
- 目录插件仍按已启用及导入偏好触发；停用、取消、删除和内容变化拒绝迟到发布。完整覆盖与逐项核验不降低，个人目录含主动清空优先。中断后仍由用户主动续做，不因持久队列擅自恢复插件任务。
- 单项补全失败不撤销已经可读的书籍，失败在既有位置重试；目录成功／失败与导入新增数量分开。

## 取消、失败与恢复

- 未开始的任务立即取消；活动 I/O 接收取消信号。解析器不支持强制中止时停止后续阶段、限制并发并释放迟到结果，不能伪称瞬时停止。
- 提交临界区开始前取消则不发布；已开始的短提交完成一致性收尾并如实报告已入库，不能显示取消后又悄悄出现书。
- 保存失败保留可核验的暂存与任务凭据供重试；设清理期限和空间上限，只清理没有被书籍／恢复任务引用的本任务文件。重试先检查持久回执，不重复建档。
- 内容变化使旧准备失效，重开／继续重新完整核验；身份未知的旧记录在锁外核验，提交时重查其修订，禁止全库锁内扫描旧书。

## 迁移与交付顺序

1. **建立测量和写入边界。** 分阶段记录耗时、读取字节、解析器峰值、锁等待及保存次数；先引入 Repository 和 Coordinator 兼容旧 API，枚举并接入所有写入方。暂用现有 JSON 适配器维持行为，该阶段不宣称已消除整库写入。
2. **交付连续管线。** 去掉四本屏障，身份前置去重、格式最小探测、连续补位和真实进度；补全队列按需打开解析器。通过取消、失败、个人数据及源文件变化回归。
3. **切换事务书库。** 在隔离副本中迁移并验证全部记录、身份、字段修订及侧存链接；切换时阻止旧写入，完成最后增量核对后原子标记唯一权威存储。旧 JSON 仅作只读备份和显式导出，不做永久双写，不让旧版本直接写同一数据目录。
4. **验证并删除旧实现。** 实测大文件、混合格式、重复导入、大书库及跨窗口；移除旧批次循环、整库快照保存和持有文档的后台队列。回滚必须包含切换后的新增个人数据，不能仅恢复迁移前 JSON。

每步都以同一组原创／授权材料比较冷、热路径。测试涵盖慢文件混合小文件、同批／跨窗口重复、不同内容同名、源文件变化、磁盘满、每个发布边界崩溃、取消重试、插件停用和阅读中保存。分别报告首本可读时间、总耗时、进度停顿、P95 提交等待和内存峰值，Node／浏览器／原生 WebView 独立验收，不用模拟测试数量替代体感。

## 当前结论

这是对调度、持久化和资源生命周期的有范围重构。已有原生 I/O、阅读引擎、格式知识与安全边界继续复用；固定四本页面调度已退场，Native／Node 写入改为变化书目事务。完整设计中的持久任务恢复、延期封面和 Web 数据库切换仍待实施；当前实现与证据以开头边界和 `PROGRESS.md` 为准。
