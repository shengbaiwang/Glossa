# Glossa 导读系统方案

日期：2026-09-10。产品范围以根目录 `PLAN.md` 为准；实现和验证事实记入 `PROGRESS.md`。

## 目标与取舍

导读的工作是在读者被原文卡住时，提供足够继续阅读的帮助。成功不是生成更多内容，而是读者能说清这一段的关系、跨过必要难点并回到原文。

只借鉴已经审阅的三个公开 skill 的方法，不安装技能包、不复制其完整提示词，也不增加模型外部工具。原始技能文件及许可核验记录见 [公开阅读 Skills 调研](../research/reading-guide-skills-2026-09-10.md)。

| 问题 | 采用的机制 | 刻意收缩 |
| --- | --- | --- |
| 内容组织：文字都认识，但不知作者为何这样展开 | Deep Book Guide：问题、依据、结论和材料作用；叙事则说明相关转折和关系 | 只解释所选正文，不从目录推测全书观点，不生成完整书评、导图或知识资产 |
| 难点解释：概念陌生、背景缺失或推理跨步 | Feynman：先用白话说明机制，再给术语；必要时用一个有边界的例子 | 最多两个真实难点，不固定输出五层解释；不为凑数制造困难，不将新术语当解释 |
| 阅读节奏：AI 文字太长，又成为第二份任务 | paper-reading-guide：短导读、逐段陪读、按需深入 | 一次一段，难点折叠，回到原文；不先看后文结论、不强制提问/答题、不自动下一段 |

## 一条完整的阅读路径

1. 打开右侧“导读”。只显示本地目录，读者先选择正在读的章节。打开面板本身没有正文提取或模型调用。
2. 本地提取所选章节，按结构组成阅读段。读者选择其中一段，看到编号、字数和起止文字；发送对象及模型服务可见。
3. 点击“生成导读”。一段对应一次有取消信号的请求；界面显示准备、接收、保存状态。切换章节、段落、书籍、模型或离开导读时中止在途任务。
4. 返回的内容通过结构和来源校验后呈现。先看到短导读和阅读提示；不理解时展开某个难点。
5. 点击引用核对本地原文，并定位到书中；保留“返回阅读位置”，验证实际跳转成功后再清除返回入口。
6. 读者自行继续读、收起面板或选择下一段。系统不会据阅读进度偷偷生成后文。

导读与现有“摘录”共用 Notebook 的收起、固定和宽度调节。非 EPUB 保持普通摘录能力。原有高亮、手写心得、草稿保护和同步能力继续使用。

## 输出协议与证据

`ReadingGuideBody` 只有四项：

- `orientation`：最多三条，每条最多 400 字符；指出局部问题及材料关系。没有足够证据时可留空。
- `difficulties`：最多两项，标题最多 80、解释最多 700 字符，默认折叠。
- `readingCue`：可空，最多 240 字符；指出回到原文值得留意的一处具体关系，不要求答题。
- `insufficientEvidence`：证据不足时明确告知，不编造内容补齐模板。

这些数值是防失控上限，提示词要求尽量短、宁缺毋滥。每条文本关联本次请求中 1–4 个不同 `sourceId`；拒绝未知来源、超限、额外字段及不完整 JSON。只允许本地来源提供引文正文和 CFI，不接受模型生成的页码或位置。

`kind` 明确区分：

| 类型 | 含义 | 展示与限制 |
| --- | --- | --- |
| `source` | 对原文内容的忠实转述 | 可核对原文；来源存在仍不等于语义已经被程序证明 |
| `inference` | 由证据支持的理解性解释或假设例子 | 标为“理解性解释”；例子最多一个，说明是假设及适用边界 |
| `background` | 原文使用但未定义的最低限度通用前置概念 | 只允许难点解释使用，标为“背景解释”，引用称“相关原文”；不把相关段落当作外部事实的证明 |

没有外部检索。背景不扩展为具体史实、日期、引文、争议判断或不确定事实；不能可靠说明时指出缺少什么。文档及元数据均为不可信输入，里面的提示词、链接和工具指令不能改变任务。生成文本作为普通文本渲染。

## 模块与上下文边界

```text
Notebook 导读入口
  → context/chapters：本地 EPUB 目录与语义来源
  → guide/passages：有界阅读段
  → guide/generate → ai/provider：首轮请求，截断时最多恢复一次，全程可取消
  → guide/schema：结构、预算及来源校验
  → guide/store：独立本地保存
  → ReadingGuideDocument：短内容与难点展开
  → citations：本地原文核验、跳转与返回
```

AI 核心仅接收 `ChapterSource` 等领域对象，不读取 Readest 状态、DOM 或 EPUB 引擎对象。模型服务沿用 provider，密钥不进入导读载荷、缓存键或日志。

阅读段以完整段落、列表、引用、表格为单位，标题与其后的正文成组；目标与上限均为 20,000 字符、最多 200 个来源。不可完整容纳的结构组明确不可用，不能截短文本却仍挂整个段落的锚点。章节解析是本地操作，发送时只取所选段的文本、来源 ID、结构类型及有界书名/章名；锚点和邻近引文定位上下文留在本地。

## 备份、数据和状态

旧实现已在移除前做快照、HEAD patch 和 SHA-256 清单。具体位置和恢复步骤记录在备份 `README.md` 及根目录 `PROGRESS.md`。这是源码恢复备份，不冒充用户书籍或浏览器数据备份。

| 处置 | 模块/数据 |
| --- | --- |
| 复用 | 章节适配、provider 与安全凭据、模型设置、来源验证和导航、Notebook 基础能力 |
| 退出使用并保留源码备份 | 全书框架、长章节学习笔记及统合、自测、反思、AI 笔记版本与导出 |
| 保持原处 | 旧 `glossa-study-notes` 数据库；新功能不打开、升级或删除它 |
| 新建 | `glossa-reading-guides` v1；每个 `[bookId, chapterId, passageId]` 只保存最新有效导读，不参与云同步 |

生成和保存分开：生成成功但写入失败时仍显示结果，提供“重试保存”；失败或取消不得替换持久化旧结果。未保存结果在本次应用会话内保留，重开面板可继续保存。读取失败先重试读取，不用空状态自动覆盖。当前会话结束前未能落盘的结果不保证跨重启恢复。

缓存键使用文档哈希、阅读段来源和锚点内容、服务标识/地址/模型、提示词及结构版本。模型或内容变化时标记旧结果，等用户主动重新生成；不在切换配置时自动消耗请求。

## 验收及下一轮阅读验证

工程验收覆盖结构分段和超限、来源与类型限制、恶意文档当普通数据、元数据预算、缓存失效、错误脱敏、取消竞争、保存重试和旧数据隔离。真实 Chromium 使用原创 EPUB 和模拟模型响应，核对完整流程、实际可见 CFI 与来源返回，并检查浅深色、窄屏、键盘、RTL 和电子墨水。

真实效果另行验证。最小材料集分别含陌生术语、背景缺口和论证跳步。人工比较使用导读前后的理解，记录读者能否解释关系、是否出现误解、来源是否支持以及是否顺利继续读下去；如解释增加负担，先删减输出或改进提示词。当前不以单测通过声称理解效果得到实证，也不为评估提前建设测验、画像或遥测系统。


## 输出截断恢复（2026-09-10）

首轮输出预算从 3,200 调整为 32,768 token，为中文结构化正文及推理保留空间。只有 provider 的可信 `length` 错误触发一次恢复：同一来源快照、65,536 token 上限，并要求更紧凑的完整 JSON；不续写半截 JSON、不扩展选中范围。网络、鉴权、限流、拒绝、格式或来源校验失败不自动重试。全过程可取消，残缺结果不保存，界面显示恢复提示并在结束时清理。

GLM-5.3/Flash 在已验证的官方 `open.bigmodel.cn` / `api.z.ai` 接口设置 `reasoning_effort: low`，其他模型与兼容服务不添加猜测参数。[官方推理文档](https://docs.z.ai/guides/capabilities/thinking) 明确该系列强制思考、不能设置 `thinking.type: disabled`，推理也消耗 token。截图证明此次响应触发长度耗尽，但没有实际请求 usage，不能断言当次推理与正文各占多少。预算增加和一次重试可能增加 token 用量；两次请求的合计输出预算上限为 98,304 token，不无限重试。提示词版本升为 `reading-guide-2`。
