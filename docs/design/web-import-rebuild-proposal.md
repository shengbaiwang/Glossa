# 网页导入重构研判与方案

日期：2026-10-29。状态：用户已授权执行，网页获取、提取、恢复与本地扩展交付已接入源码；当前验证与平台边界见 `../../PROGRESS.md`。下文问题表与原始验证记录保留为改造前证据，不代表修改后的行为。

用户反馈各种网页均有失败，以普通文章、博客、学术网页为主，允许考虑推倒重做。本轮检查当前仓库源码、相关测试与官方提取库文档，进行了无网络的隔离库行为验证；没有获得具体失败 URL，没有重放用户真实导入或验收日常安装版，不能据此给出实际成功率或把所有失败归因于某一处缺陷。

## 结论与取舍

建议替换网页获取、正文提取及失败恢复的核心流程，保留插件入口、统一导入反馈、EPUB 阅读和持久入库边界。仅换 Readability、不断增加站点选择器不足以解决当前问题；删除整个导入与阅读体系也没有必要。

第一优先是普通公开文章可稳定导入，其次是学术内容结构保真，最后补齐登录和动态页面。新提取器以 Defuddle 为首选评测候选，保留 Readability 作基线及低质量结果的备用；默认顺序在同一份材料的对照评测后确定，不能先假定 Defuddle 全面优于旧库。

## 已确认的源码问题

| 环节 | 当前行为与证据 | 影响与证据边界 |
| --- | --- | --- |
| 短文判定 | `convertToEpub.ts:561` 起，将正文少于 400 字符统一判为 `login_wall`；站点规则也受 400 字符门槛约束 | 正常短文会被拒绝，字符数不能证明登录或验证状态。隔离原创短文经 Readability 提取成功，正文 185 字符，落入当前拒绝条件 |
| 备用提取 | `convertToEpub.ts:536` 起，Readability 抛错或无内容立即退出；通用选择器仅在它返回短内容且原 HTML 超过 50,000 字符时运行 | 最需要备用方案的失败路径无法到达备用提取；小而正常的网页也失去补救 |
| 元数据 | `sanitize.ts:100` 使用默认 DOMPurify 全文清洗后再解析；元数据回退在 `convertToEpub.ts:584` 之后读取清洗结果 | 使用已安装库验证，`meta[name=author]`、`og:title` 和 JSON-LD 均被移除。标题仍可能来自 title/h1，但作者及结构化元数据回退不可靠 |
| 页面就绪 | `clip_url.rs:585` 在 load 后固定 3 秒捕获，20 秒强制捕获，外层等待最多 30 秒 | 未根据正文出现和稳定性决定时机；动态正文、重定向及懒加载的实际失败占比待原生实测 |
| HTML 回传 | `clip_url.rs:550–573` 将整页 HTML 转为 Base64 放进 localhost 跳转 URL | 回传体积膨胀，并引入长 URL／导航兼容性风险；本轮未测得特定系统的长度极限，不宣称这是所有长文失败的原因 |
| 桌面恢复 | `clipSignIn.ts:107` 只允许移动端进入登录后的手动捕获 | 桌面即便普通浏览器能打开页面，也缺少在应用内完成登录／展开正文后继续捕获的路径 |
| 最终网址 | `clip_url` 只返回 HTML 字符串，转换沿用用户最初输入的 URL | 重定向后相对链接和资源可能解析到错误位置，来源记录也缺少最终 URL |
| 内容保真 | `sanitize.ts` 的最终白名单不包含 MathML、SVG；`assetBundler.ts` 返回 missing，网页调用方未向用户传递 | 学术公式／矢量图存在结构损失；图片缺失可能被当作普通成功。不能将生成 EPUB 等同于完整可读 |
| 工作线程 | `conversionWorker.ts` 明确将 page 转换放回主线程，以访问 Tauri HTTP | 换算法时还需测主线程耗时，不能根据函数名声称已在后台运行 |

现有通用站点规则主要针对微信公众号和 X 文章，不能据此认定已覆盖普通博客、资讯及学术出版站点。

## 算法及获取方案比较

| 方案 | 适用性 | 建议 |
| --- | --- | --- |
| 修正当前 Readability 管线 | 不增加运行时；可立即修复误拒绝、备用路径与元数据清洗顺序 | 必做的基线修复，但单独做完仍缺少完整获取和恢复能力 |
| Defuddle + Readability 备用 | Defuddle 提供 HTML 输出，针对脚注、公式、代码块和元数据做标准化，适合本项目的阅读目标 | 首选评测路线；按质量触发备用，不把两个结果直接拼接，也不以“文字最多”选胜者 |
| Trafilatura | Python 正文及元数据抽取工具，有公开可重现评测 | 用作离线对照候选；现阶段引入 Python 运行时增加桌面／移动交付成本，暂不作为应用默认依赖 |
| Jina Reader 等托管抓取服务 | 可代管页面获取、渲染和提取 | 暂不作为默认依赖；增加外部 URL／内容流转、联网及服务依赖，也不继承用户浏览器登录态 |
| 浏览器当前页捕获 | 直接读取用户已打开、已登录、已展开的 DOM | 登录／强动态页面的重要补充，不能代替普通 URL 导入的基本可靠性 |

Defuddle 的选择依据来自其设计适配性，不是本轮已经完成了中文网站成功率比较。其异步提取器可能使用第三方 API；接入时固定版本，默认同步本地提取并明确设置 `useAsync: false`，用断网测试确认没有隐式外发。调试模式可能含被移除的正文片段，不可直接写入日常日志。

参考：

- [Defuddle 官方 README](https://github.com/kepano/defuddle)：输出、标准化、运行环境和第三方回退行为。
- [Mozilla Readability 官方 README](https://github.com/mozilla/readability)：DOM 提取、基准 URL、独立清洗与 CSP 要求。
- [Obsidian Web Clipper 故障排查](https://obsidian.md/help/web-clipper/troubleshoot)：自动提取仍可能漏内容，提供选文和模板作为恢复手段。
- [Trafilatura 官方文档](https://trafilatura.readthedocs.io/en/latest/)及[评测说明](https://trafilatura.readthedocs.io/en/latest/evaluation.html)：Python 定位及评测方法；不将其评测分数直接换算为 Glossa 的实际成功率。
- [Jina Reader 官方仓库](https://github.com/jina-ai/reader)：轻量 HTTP 与浏览器获取引擎、就绪条件和托管服务接口。

## 建议的新流程

```text
用户主动导入 URL
    ↓
有界 HTTP 获取 → 正文足够且结构可信 → 提取／整理
    ↓ 未取得可用正文
隔离 WebView 渲染 → 正文出现且稳定 → 提取／整理
    ↓ 仍需登录、验证、展开或人工指定正文
同一捕获窗口显示原网页 → 用户操作 → 保存当前正文／所选内容
    ↓
质量判断 → 安全清洗与资源归档 → EPUB → 现有持久入库
```

### 1. 获取完整页面

- 普通公开网页先用原生 HTTP 获取，处理编码、响应类型、重定向及最终 URL，避免每篇文章必开临时窗口。响应实际为 PDF 时转交现有 PDF 导入；学术摘要页有全文链接时显示明确选择，不把摘要冒充全文或自动遍历链接。
- HTML 不足时才启用隔离 WebView。根据正文节点出现、正文文本／节点变化趋稳、资源状态和总时间预算决定捕获；不能只靠网络空闲，因为追踪请求可能持续运行。受预算约束的滚动可触发懒加载，但不得无限滚动或自动点击所有按钮。
- 当前网址、最终网址、有效 base URI 和捕获方式一起返回；canonical 作为来源候选记录，不直接支配身份合并或无条件改变资源解析基准。
- 替换“完整 HTML 塞进导航 URL”。先对 macOS 做最小原型，使用平台脚本求值／专用消息桥返回受大小约束的数据；移动端已有 evaluateJavaScript 形态可参考，但桌面接口和容量必须独立验证。
- 远程页面与应用 WebView 隔离，不获得文件系统、密钥或通用 Tauri 命令权限。捕获桥只接受当前任务、窗口及主框架的一次性结果。取消关闭捕获窗口、撤销句柄并清理临时内容，停用拒绝迟到发布。

### 2. 正文提取与质量判断

- 将元数据读取与正文清洗分离。用不执行脚本、不加载外部资源的解析环境读取有界 JSON-LD、Open Graph、Dublin Core／citation 元标签；JSON 仅作为数据解析，最终输出继续严格清洗。
- 同一快照先尝试主提取器；无结果、报错或低质量时尝试备用和少量已验证站点规则。每次使用独立 DOM 副本，避免前一算法修改 DOM 后影响后一算法。
- 质量判断综合文章语义节点、标题与正文一致性、段落连续性、链接／导航比例、验证码／登录表单／订阅遮挡等信号；不得仅凭长度或单个“登录”关键词拒绝。
- 短文、图片为主的文章和摘要分别处理。短而完整可以成功；图片文章以资源可用性判断；摘要可作为摘要导入，但明确其范围。多个候选分歧较大时提供轻量预览或选文捕获，不自动拼接成不存在的原文。
- 继续以 HTML → EPUB 为主，避免先转 Markdown 再转 HTML 丢失复杂结构。保留脚注互链、表格、代码、图注、可访问公式结构；对 MathML／SVG 制定专用安全白名单，不能直接打开所有标签／属性。
- 自动识别只能评估“当前已获取快照”中的完整性，不能证明站点没有隐藏后续内容。分页文章、折叠参考文献及全文与摘要分别在验收中检查。

### 3. 资源、来源与持久保存

- 图片下载沿用有界并发，补充流式体积限制和总耗时预算；已有每图限制是在读完整资源后判断，不能称作内存硬上限。正文、图片与可选封面分阶段反馈；封面失败不阻止导入。
- 图片／公式缺失保留位置和原链接，明确显示缺失数量并允许重试，不能悄悄抹掉关键证据。补资源不得无条件重写已入库正文和锚点；有笔记或阅读位置时，须做修订核验或另存版本。
- 保存原始／最终来源 URL、站点、作者、发布日期、捕获方式、算法版本和缺失资源信息；抓取时间作为旁存记录，不让每次时间变化都改变相同内容的 EPUB 字节。
- 沿用完整内容指纹与统一持久提交，保存成功才显示完成。同 URL 不等于同内容，不覆盖旧网页版本上的改名、分组、进度、笔记和高亮。
- 跨算法或跨捕获渠道的输出字节可能不同，不能延续“同 URL 必定产生完全相同 EPUB”的承诺。完全相同快照／资源的输出应确定；疑似同源版本只建立关联或交由用户选择，不自动合并个人记录。
- 失败分为获取失败、等待正文超时、需用户操作、正文不确定、资源不全、打包失败和保存失败。重试从仍有效的最近阶段恢复，最终仍重查取消、插件代际和书库最新状态。

### 4. 界面与浏览器后备

- 保持现有「导入网页」弹窗：粘贴 URL 后自动选择路径，只显示当前真实阶段。普通成功不新增编辑表单或额外确认。
- 需要用户操作时，原位提供「打开网页继续导入」。捕获窗口显示网页，保留「保存当前正文」和取消；选择一段内容后可保存选文，清楚记录为摘录。
- 低质量或可能截断时才显示紧凑预览，标题与作者可原位修正。键盘、触屏、焦点恢复和电子墨水反馈继续共用现有规则。
- 后续浏览器扩展以当前标签页捕获和本机交付为目标。仓库已有 `extensions/send-to-readest`，可以复用捕获技术；其 `background/upload.ts` 默认上传 `https://web.readest.com/api/send/inbox/file`，不能直接当作 Glossa 本机剪藏通道。先通过 EPUB 文件导入打通，再独立设计受用户触发的本机传输；不搬运浏览器 Cookie。
- 桌面优先验收；浏览器环境存在跨站获取限制，不能宣称原生 HTTP 路径在纯 Web 已可用。移动端与系统分享继续单独验收。

## 保留、替换和不引入的部分

保留 `webImport` 插件生命周期、导入进度组件、核心完整指纹与数据库提交、已存书籍和个人数据，以及经过核验可复用的 EPUB 打包／目录／资源模块。`convertToEpub.ts` 同时服务 DOCX、RTF、TXT、HTML、article 和 page，不能整文件删除。RSS 与浏览器扩展调用方必须分别回归。

替换固定等待捕获、整页 URL 回传、仅按 400 字符判失败及不连通的备用流程；调整过早丢弃元数据与公式结构的清洗边界。站点规则应进入同一质量判断，而不是匹配即信任。

首轮不引入 LLM 正文重写、默认云端抓取、自维护爬虫集群或整套 Playwright 浏览器随应用分发。正文采集不应为了“看起来成功”生成原文没有的内容。

## 分阶段交付与验收

1. **基线与确定性修复。** 建立按阶段统计；复现短文、空结果备用、元数据及重定向问题。至少准备 40 个代表页面，建议 24 个普通文章／博客、10 个学术页面、6 个登录／动态页面；中文与英文、短文与长文、图表／公式／脚注均覆盖。用户后续提供的失败 URL 纳入同一集合，不阻塞先修源码确定的问题。
2. **普通网页路径。** HTTP 优先、提取器候选评测、安全元数据处理、短文质量判断、资源缺失反馈、来源保存接入。保持 EPUB 与现有持久入库契约；用固定快照比较算法，用真实 URL 验证获取，两种结果分开记录。
3. **原生捕获与恢复。** 先验证 macOS 桥接原型，再交付自适应等待、最终 URL、取消／停用清理和可操作捕获窗口。覆盖大 HTML、慢页面、重定向、登录、手动展开和迟到结果。
4. **浏览器当前页交付。** 在普通 URL 和桌面捕获可用后，复用现有扩展的 DOM 捕获，交付明确的本机接收路径；平台安装与权限流程单独验收。

提议的首轮门槛：普通公开文章测试集中至少 90% 经人工检查可直接阅读、无关键正文缺失；旧版成功样本不得出现未解释的退化。90% 是验收目标，不是当前测量结果，也不是总体网站成功率承诺。学术页面另查正文首尾、章节、表格、脚注、参考文献、公式和图片；不能用平均提取字数替代。验证码／登录页面误入库必须为零。记录 p50／p95 总耗时、分阶段耗时、峰值资源与资源缺失率。

取消、插件停用、保存失败、重复导入、重试、重开、跨窗口新编辑均须覆盖。真正完成包含 macOS WebView 端到端打开、导入、离线阅读验证，不能仅凭 jsdom 或浏览器模拟通过。
