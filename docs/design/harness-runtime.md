# 阅读 harness 的执行与质量闭环

日期：2026-09-23。用户已采纳成熟方案的机制借鉴，授权因地制宜完善现有架构。

## 架构选择

沿用格式适配器 → 阅读任务策略 → provider 的边界；对话与导图共享有界调度、派生清单存储和安全诊断。普通问答保持流式短路径，完整总结保持全范围读取。不引入工作流服务、云追踪、多 Agent 或向量库。

借鉴 [LangGraph 检查点](https://docs.langchain.com/oss/javascript/langgraph/checkpointers) 的可复用阶段结果、[LangSmith 评测闭环](https://docs.langchain.com/langsmith/evaluation) 的固定样本及运行记录、[Claude SDK 上下文管理](https://code.claude.com/docs/en/agent-sdk/agent-loop) 的按任务组织材料、[PaperQA2](https://github.com/Future-House/paper-qa#paperqa2-algorithm) 的证据筛选。只采用机制，不引入这些框架作为运行依赖。

## 本轮实现边界

- **证据与输出契约**：阅读清单的提示词 schema 与运行时校验共用；格式、结构、覆盖和来源错误提供固定安全反馈，在既有请求/总时限内至多两次定向纠正。导图长范围汇总同时收到清单对应的完整原文，超出有界汇总材料时明确收窄，不能截断后伪称完整。阅读总结沿用清单观点的来源去向检查；导图允许合并为最多 24 个节点，不能以来源 ID 数量代替观点覆盖或语义蕴含的验收。
- **诊断与评测**：本机阅读回答版本保存有界阶段轨迹，记录阶段、耗时、数量、缓存及错误类别，不记录问题、正文、原始响应或凭据。建立原创反例集及模型审校协议，区分支持、矛盾、证据不足；审校自身以人工标定反例验收，不用自评分宣称正确。默认生成不增加未经质量/耗时评测的第二轮模型审校。
- **恢复**：将阅读总结的已校验清单保存为独立、有界、可丢弃的本机派生缓存；再次主动重试时重新完整读取、核对材料/问题/提示词/模型配置后复用。只保存派生观点，不复制正文。取消不提交新缓存；缓存故障退回正常流程。导图既有必须成功的任务检查点与个人编辑机制保持。
- **上下文**：引用开启的阅读历史按最近上下文和当前问题相关性选择完整轮次，每份来源重新核验；长轮次不阻断更早的可用轮次。不引入未经评测的模型摘要，不将推断写成长期事实；关闭引用继续不携带旧阅读材料。
- **调度**：相同端点的导图与对话共用两个槽，等待队列优先交互问答，并以有限连续优先次数防止长任务饥饿；429 遵守 Retry-After 并暂时降并发。排队和重试纳入调用方既有时限。限额仍为单窗口，不声称跨窗口供应商总配额协调；服务参数仅采用已确认能力。

## 验收

工程回归覆盖：同端点交互优先/公平性/429/取消；无来源、假来源、漏覆盖、错误纠正和预算耗尽；缓存跨实例复用、版本变化失效、损坏与存储不可用；原文与旧历史隔离；轨迹不含任意文本。Chromium 验证真实 IndexedDB 容量/事务及既有阅读与导图流程。

新增 12 条原创且预先人工标定的反例，评测入口为 `harnessEvaluationLive.test.ts`，一次请求、120 秒；通过 `GLOSSA_EVIDENCE_LIVE_CONFIG`、内存中的 `GLOSSA_EVIDENCE_LIVE_API_KEY` 和可选 `GLOSSA_EVIDENCE_LIVE_REPORT` 显式启用。期望答案不发给模型，只在本机比较。原有 `mindmapLive.test.ts` 检查实际生成；两者需合计遵守用户授权额度。

语义验收分别报告原创样本的支持判断、否定/条件/因果/同名异义错误、最终生成的人工复核与端到端耗时。真实 API 默认关闭，沿用显式调用额度授权；未执行的实测不标为通过。未经验证不默认启用自动语义修复或承诺 P50/P95 改善。
