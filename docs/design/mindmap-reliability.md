# 导图可靠性：输出契约、有限纠错与真实验收

日期：2026-09-23。目标是解决模型已经响应但一张有效导图也无法得到、重试仍重复同一失败的闭环缺陷。执行事实和验证结果单独记录在 [PROGRESS.md](../../PROGRESS.md)。

## 失败原因与修复边界

旧流程把任意文本交给严格解析器，短章同时出现裸图与外层包装示例。解析失败、超长标签、额外字段、漏覆盖和非法来源共用一句报错；请求却已记录为 `received`。仅截断/超时能恢复，主动继续也不知道前次为什么失败。

新的 `protocol.ts` 由接受输出的同一 Zod schema 生成提示词契约：短章 `{coveredSourceIds,map}`，清单 `{coveredSourceIds,points}`，汇总/分支 `{nodes,insufficientEvidence}`。每次只有一种外层形状。树的唯一根、父子关系、深度、条件与引文要求仍明确写入提示词；不能序列化进 JSON Schema 的树约束继续在本机校验。

导图通过 provider 显式请求 `response_format: {type: "json_object"}`。这符合 [MiMo 结构化输出文档](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/text-generation/structured-output)和 [DeepSeek JSON 模式](https://api-docs.deepseek.com/guides/json_mode/)；JSON 模式不保证业务 schema 或语义正确，因此不会代替本机核验。普通对话不带此参数。

服务明确返回参数不支持时，由生成流程在原预算中消耗一次恢复，记住本任务的纯提示词模式；未知 400、鉴权或网络错误不据此降级。该选择与当前任务版本/模型/端点绑定，不是跨服务的永久能力缓存。

## 校验与恢复

1. 响应大小有界，解析 JSON，按严格 schema 验证；只兼容完整代码围栏，不猜测字段、不替换引文、不截短模型观点。
2. 短章和清单必须逐一包含本次提供的全部来源 ID，无重复、无缺失；每条观点/节点只能引用该阶段允许的 ID。最终汇总只使用清单实际引用的来源。
3. 失败记录四类：格式、结构、覆盖、来源。诊断只含最多 8 个问题，每个路径最多 8 段白名单字段/有界索引和固定规则码；任意模型字段名、Zod 原始 message、失败响应、服务正文不会进入检查点或纠错提示。
4. 在相同完整材料和契约后加入安全的失败反馈，生成一个完整候选，重新执行全部校验。每次主动运行共享两次恢复，连同格式回退、截断/超时/限流恢复一起计数；仍最多 26 次 provider 调用、8 分钟，并保留原阶段限时和汇总额度。
5. 短章最多一次定向纠正；仍失败则记住跳过直接成图，剩余额度允许时转完整清单，再汇总。没有额度时停止并保留状态，下次主动运行从清单开始。清单和汇总使用剩余共享额度纠正，失败阶段不会被计为已完成。
6. 业务校验完成后才记 `valid`，校验失败为 `invalid` 并附安全诊断。`valid` 仅表示本次响应通过协议，不等于最终成图或证明语义准确；证据不足、持久化失败仍不能生成完整图。旧 `received` 可读但不会被解释为新协议成功。

检查点保存阶段错误、是否改走清单、是否曾明确拒绝 JSON 模式。成功后清除该阶段失败状态，取消后不接受迟到输出。重开仅加载元数据，仍须用户主动重试并重新本机核对原文。零进度显示“重试生成”，存在已保存清单才显示“继续生成”。

版本为 overview-4 / inventory-4 / branch-2。新键隔离旧中间结果；旧成图、来源与个人编辑继续读取，原数据库不清理。编辑树不会被纠错流程覆盖。

## 验证方式

单元回归覆盖输出类别、字段长度、额外字段、非法 ID、漏覆盖、安全错误路径、相同完整材料重发、恢复额度、并发格式回退、取消和跨重开策略。真实 Chromium 验证 IndexedDB 的序列化/冲突/回滚、原创 EPUB 成图/来源跳转、个人编辑保留与恢复 UI。

`apps/readest-app/src/__tests__/glossa/mindmapLive.test.ts` 是默认跳过的真实 API 验收入口。它只包含原创材料，调用生产 `generateOverviewMap` 和 `streamCompletion`，替换的是阅读材料及检查点存储。三份样本覆盖中文限定/反例、英文复制权限的双条件、跨章“开放”同名异义；最多 8 次实际生成 provider 调用，单任务仍遵守生产预算，不调用用户书籍。

显式授权后，在内存中提供 `GLOSSA_MAP_LIVE_API_KEY`；`GLOSSA_MAP_LIVE_CONFIG` 指向仅含普通 provider 字段的 JSON 文件，`GLOSSA_MAP_LIVE_REPORT` 指向本机报告路径。用 Node 24 运行 Vitest 的该文件（`--maxWorkers=1`）。不得把凭据填入命令行、配置文件、日志或提交。普通 `pnpm test` 没有这些变量时不请求网络。可用 `GLOSSA_MAP_LIVE_CASES` 选择原创样本索引（0、1、2），用 `GLOSSA_MAP_LIVE_MAX_CALLS` 将本次额度进一步收紧到 1–8；重复运行须合计遵守用户授权的累计请求上限。

自动断言只判断有效成图、保存协议、来源数量和预算。报告保留原创输入、各节点和无正文请求诊断，用于逐条人工评阅：

- 主论点及结语有没有去向；并列条件是否被改成任选条件。
- 否定、例外、反例适用范围及意见分歧是否丢失。
- 关系词及解释是否由所列来源支持，是否把相关变成因果。
- 跨章相似词是否错误合并，是否把中间清单当成新原文。

不能以来源 ID 合法、阅读回执齐全或大量模拟测试通过宣称“语义已验证”。少量原创样本也只证明这些案例；真实书籍、长范围与不同模型的质量仍需独立扩大验收。
