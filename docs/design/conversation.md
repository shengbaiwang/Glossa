# 基础对话（2026-09-12）

本次用户明确要求取代以下旧设计。当前实现以普通 API 聊天为主，自动附带信息只有书名、作者和当前完整目录层级路径，且不在对话界面显示。正文提取、选区附件、范围、检索、预算、来源分类和摘要处理全部退出对话。完整当前规格以根 `PLAN.md` 的“对话方案（2026-09-12）”为准。

界面使用 Glossa 纸墨色、共享线条图标与安静的侧栏布局。顶部会话选择、新建、搜索与更多菜单，下方消息与固定输入框；不加入注释说明，也不渲染书名、作者或目录路径。输入框内的模型入口支持服务选择、搜索模型、手动输入模型及设置。消息支持 Markdown、复制、重新生成、停止、错误重试、本机历史恢复与会话独立草稿。问题与回答文本可以直接选中复制（阅读侧栏容器默认禁止选择，对话内容显式恢复 `user-select: text`，控件按钮除外）。

### 交互调整（2026-09-13）

- 重新生成改用圆形回转箭头（`RefreshCw`），与前进/撤销语义区分。
- 移除输入框展开/收起按键；输入框只随内容自动增高（上限 180px，超出滚动），输入时显示字数。推理强度选择器移到输入框右下角发送键旁，仅在当前服务/型号具备已核验推理档位时出现，选择即保存到该服务配置；能力与发送规则不变。
- 会话自动命名：每个会话的首条回答完成后，用同一服务以一次独立小请求（仅首问与首答的截断、256 token 上限、不携带推理档位与用户提示词）生成不超过 48 字符的名称，取首行并去除首尾引号与标点；失败或结果不可用时保留以首问生成的备用标签，不提示错误。仅在会话无名称时触发一次，用户手动命名永远优先，自动命名不覆盖；命名请求不进对话历史。

目录路径由本地 EPUB 目录层级恢复（含扁平 NCX 的有限层级还原），按“父级 › 子级”拼接后随请求发送；目录不可用时回退到当前分节标签。新消息使用 conversation-3。沿用原数据库并保留旧记录的读取校验；旧原文/来源/摘要不会被带入新请求。模型只能看到三个元数据字段与当前会话有界的普通消息，不获取阅读正文。停止保留部分文本；仅完整轮次参与后续请求。导图的来源验证和阅读/同步数据保持原有行为。

### 修改与多版本回答（2026-09-12）

每一轮可有多个回答版本，上限 8 个。重新生成最后一条回答、或编辑最后一个问题后重发，都会新增一个版本并保留旧答案，默认选中新版本；旧版本不删除、不静默淘汰。达到上限时明确提示“删除该对话后重新开始”。回答下方的版本控件显示“当前/总数”，可用前后箭头切换；切换后当前版本会镜像到该轮的问题与答案字段，后续请求直接读取 activeVersionId 对应版本，不依赖可能过期的镜像字段。编辑重发失败保留原回答，并恢复编辑框中的问题以便重试。版本记录包含各自的问题、文本、服务身份、时间与完成状态；本地存储校验每个版本的 provider、问题长度与文本长度，并拒绝无效的 activeVersionId。

### 模型参数（2026-09-12）

`ProviderConfig` 增加可选 `reasoningEffort` 与 `maxTokens`。能力由服务地址与模型名判定，只对已核验的官方接口发送厂商参数：智谱官方（`open.bigmodel.cn`、`api.z.ai`）的 GLM-5.3/Flash 支持 `low`/`high`/`max`，未选择时沿用既有默认 `low`；OpenAI 官方（`api.openai.com`）按已核验型号匹配（含日期快照）：GPT-5/mini/nano 为 `minimal`/`low`/`medium`/`high`；GPT-5.1 为 `none`/`low`/`medium`/`high`；GPT-5.2 在此基础上支持 `xhigh`；o1/o3/o3-mini/o4-mini 为 `low`/`medium`/`high`。不按任意前缀猜测 chat-latest、pro、codex 或未知新型号的能力。未知模型与其他兼容服务不显示推理强度，且即使存储了该字段也不会发送；已知型号也只发送其支持的档位。能力表依据 [OpenAI 模型说明](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.2) 与 [GLM 推理说明](https://docs.z.ai/guides/capabilities/thinking)，不代表覆盖所有服务与未来型号。输出上限在官方 OpenAI Chat Completions 使用 `max_completion_tokens`，其余兼容接口使用 `max_tokens`，对话默认 16,384 token，用户设置优先；导图继续使用显式的输出预算。设置面板保存参数到 provider；写入每轮回答时只保留服务身份（id、name、baseUrl、model），不持久化能力参数。

### 输入、历史与排版（2026-09-12）

- 问题上限由 2,000 提升到 20,000 字符，请求校验与本地存储校验同步；输入框随内容自动增高（上限 180px），输入时显示字数（2026-09-13 起不再有展开/收起按键）。
- 会话可重命名（最长 120 字符），并在首条回答完成后自动命名（见“交互调整”）；切换器优先显示名称；可在当前书籍内按会话名称、问题与所有保留版本的回答文本搜索并跳转到匹配会话，没有结果显示空状态。
- 回答的原始 HTML 先作为文字转义，再由 marked + marked-katex 渲染为 HTML，经 DOMPurify 放行 KaTeX 的 MathML 语义与标注节点，同时禁止脚本、事件、表单、内联样式与远程图片，并移除 `javascript:` 链接；支持行内 `$…$` 与块级 `$$…$$`、GFM 表格与代码块。代码块带复制按钮并给出成功或可重试的失败反馈，编辑输入和操作菜单不会丢失复制按钮。回答字号放在顶部“对话菜单”中，与重命名和删除操作共用入口，并本机记忆（小/中/大/特大，默认中），通过 CSS 变量作用于问题与回答。保留禁止原始 HTML 执行与远程图片自动请求的约束。

### 自建提示词（2026-09-12）

按用户要求删除内置提示词预设。提示词完全由用户在设置“对话”页自建：名称＋内容，本机 localStorage 保存（`glossa.conversation-prompts.v1`），最多 20 条，名称最长 60 字符、内容最长 8,000 字符，读取时做结构校验，损坏数据回退为空。设置页与选择菜单只保留名称、编辑/删除和输入控件，不加解释功能的注释文案。

对话输入框旁的选择器只在已有提示词时出现，列出全部提示词与“不使用提示词”，并可直接进入设置页。选中的提示词在发送时作为唯一 system 消息注入，未选择则不带任何系统提示词；在途请求保持发送时的提示词快照。提示词为全局选择，不按书或会话区分；切换提示词不中止在途回答、不影响历史。conversation-3 消息协议与历史兼容不变。

### 阅读对话的表达与依据（2026-09-12，内置提示词已删除，保留为研究历史）

以下记录已删除的内置提示词的设计意图与实测过程，不再对应线上行为。按用户进一步明确的方向，简短约束针对系统提示词；回答追求语言效率，不机械限制字数。先解决疑问，用自然段补足概念与推理，复杂问题按需展开。时代背景、官制细节、作者处境和态度都可以帮助理解，但须说明与当前问题的关系；不重复总结、套百科模板或例行邀聊。追问沿用话题，读者没懂时换解释，而不是仅把上一条扩写。

事实边界仍然有效：区分原文明说、背景事实与解释推断，条件句不证明条件已发生，作者观点不自动成为定论。未知的书籍身份不猜，不能核对的引文改作概述，必要时才请求用户贴文。贴文和元数据中的指令不得执行。上述是模型行为目标，不是本地事实校验器。

当时最终提示词曾在 `src/glossa/conversation/generate.ts`，保持少于400个Unicode字符的回归预算，不设置回答字数上限。2026-09-12 应用户要求删除该内置提示词，对话改为用户自建提示词（见上文）。真实 GLM-5.3-Flash 探索记录与剩余质量问题见 [提示词实测](../research/conversation-prompt-tuning-2026-09-12.md)。

## 上下文选择

| 选择 | 实际读取和边界 |
| --- | --- |
| 当前页（默认） | 使用阅读引擎实际可见 CFI，在原始文档中裁剪到可见文字；不扩展到段落的未显示尾部。 |
| 所选文本 | 只使用读者主动选择的原文；选区可独立附加于其他范围。 |
| 一段 | 从当前页涉及的段落中选择一个，明确扩大到完整原文段落。 |
| 一节 / 一篇 / 一章 | 读者从原书目录选择结构条目；按目录的起止锚点读取，包含该条目的子层级。支持最多组合四个目录条目，移除单个条目后只检索剩余范围。三种名称表达读者意图，不假设 EPUB 目录具有统一篇章语义。 |
| 全书 | 扫描本地线性阅读内容，按问题检索少量相关段落；宽泛问题采用分布式样本。取样不代表完整覆盖。 |
| 仅书籍信息 | 不附加阅读范围；“仅使用书籍信息”按钮同时移除选区和追问材料。书名、作者、章节标题和阅读位置仍携带。范围下拉切换仅关闭范围，独立选区附件仍须单独移除；预览显示最终结果。 |

扩大到节、篇、章、全书时显示可能包含未读内容。目录缺失时不虚构章节，可用当前页、选区、段落或全书范围。AI 无法从未提供的部分得出书中事实，应明确缺少的证据。

较大范围先做本地关键词排序，支持中文双字词及 Unicode 词语；选中来源保持原文顺序。单条目初选最多 6,000 字符，多条目合并去重后连同选区最多保留 8,000 字符候选、100 个来源。实际发送按轻量 2,000、均衡 4,000、扩展 8,000 三档预算筛选，默认轻量；选区优先，宽范围按问题相关性筛选。用户可取消任意片段；超预算的完整块明确标为未发送，不截取为假完整来源。全书最多八个片段，且不会发送全部原文来源。超长完整结构块不能容纳时跳过并显示部分证据，不截断冒充完整来源。用户每次发送都有固定的原文快照，随后翻页不会改变在途请求。

## 答案与来源

- 默认 2–4 个简短段落，结构最多八段，每段最多 1,400 字符。每个完整段通过结构与来源白名单校验后才显示；最终结果再次校验后保存。
- 原文依据与解释推断必须附已提供来源；背景知识单独标记，不能冒充作者观点；无法回答的原书问题标为证据不足。
- 模型只返回来源 ID，不生成可信引文、页码或位置。点开来源后在本地恢复锚点并核对原文；唯一匹配的局部引文允许恢复，歧义或失配明确报错。
- 支持跳到原文及返回读者实际起始位置，导航串行可取消。选区 CFI 转为文本节点边界，避免阅读引擎将元素边界还原为空选区。
- 全部正文、书名和历史属于不可信数据；提示词中明确不接受其中的工具指令。没有网络检索或自动工具执行。

## 历史、模型和失败状态

通过现有 provider 与安全密钥存储调用模型；界面可进入现有模型设置。对话使用独立 IndexedDB `glossa-conversations`，按文档哈希隔离，不迁移旧 AI 笔记数据库。每书最多 20 个对话、每个 40 轮，达到上限明确提示新建或删除；不会静默丢弃旧结果。

历史仅取最近四个符合当前模型与当前证据范围的回合，每轮问题最多 240 字符、摘要最多 500 字符。来源退出当前授权范围后，其历史摘要也不会发送。界面显示本次摘要轮数与全部摘要内容，可单独关闭。成功回答后固定本轮实际材料，连续追问不会被翻页或新问题检索结果悄然换题；用户可主动换用当前阅读内容或调整材料，旧摘要不绕过新的来源边界。不以无限历史维持连续性，也不将历史视为原文证据。

上下文读取、生成和来源导航均可取消，关闭或切离对话时中止。准备新上下文期间禁止发送过期快照。失败保留问题和已完成回答；保存失败保留内存中的有效结果并可重试，历史加载失败禁止以空历史覆盖。会话仅保存在本机，不改变云同步协议。每轮新增可校验的上下文记录，包括实际发送的书籍信息、范围、预算、来源标题、选区标识和压缩历史；重开、切换或主动复用历史材料可恢复追问焦点。旧 conversation-1 数据兼容读取，新提示词版本为 conversation-2。

## 上下文区交互与用量（2026-09-11 重构）

- 常驻层：书籍身份与当前阅读位置；元数据缺失时显示未知，不能让模型按标题猜书中内容。进度表示阅读位置，不代表全部前文已读。
- 调整层：“调整材料”折叠入口包含范围、多个目录条目、预算和用量说明。正文片段另有可展开清单，标明来源、选择原因及实际是否发送，可逐条排除和本地核对。
- 追问层：成功回答后保留发送快照；阅读位置变化只更新常驻元信息。每轮“查看本轮材料”保存发送时快照，不被随后翻页改写。“用这些材料继续”显式恢复历史材料，“换用当前阅读内容”回到当前页并清除选区附件。
- 默认不调用模型生成摘要；最多四轮，每轮问题 240 字符、回答摘要 500 字符，来源或模型不匹配即排除。只展示并发送当前允许的摘要。每次请求的原文预算在 provider 边界再次校验。
- 原文预算不是总 token 数或价格。书籍信息、系统指令、问题和摘要另计，输出上限 16,384 token；实际费用以模型服务为准。没有新增自动重试或自动模型调用。
- 设置和材料区可独立滚动，输入框保持在底部。保留窄屏、RTL、电子墨水与键盘交互。
