# 全书阅读对话 harness

日期：2026-09-22。用户在明确了解默认全书查阅的范围后授权实施，目标是逐步接近 NotebookLM 的核心阅读对话体验。该授权取代初版仅附件边界；原始调研见 [阅读 harness 案例](../research/reading-harness-assessment-2026-09-21.md)，当前行为以 `PLAN.md` 为准。

## 阅读者看到的行为

可重排 EPUB 输入区默认显示「全书」，对话可在当前书中查阅，包括未读章节。只有发送问题才读取原文并请求模型；打开面板、翻页、新建会话、切换范围不扫描全书或请求模型。模型配置、用户提示词、Markdown 流式回答与取消沿用现有入口。

范围菜单仍可引用当前可见页、所选文字或明确的章节阅读段。页/选区严格裁剪，阅读段保留完整语义块，附件按会话保存为固定快照，翻页不更新。选区核验失败不得回退到整页。移除附件回到全书，新会话默认全书。保留旧附件与会话，其他格式继续基础对话，不恢复 AI 导读。

## 两种读取流程

**具体问答：** 优先用原问题做本地 BM25 检索，命中后直接进行一次可见的流式回答；不固定先调用模型规划。没有命中时才用问题、目录和同范围历史问题扩展最多四个短语，计划章节 ID 必须属于本地白名单，且该回退不能开启全书观点清单。点名的唯一章节或明确的当前章直接约束读取范围。中文使用分词和 CJK 双字词，多个查询交错选取完整原文块，并保留邻近限定条件。选取几个观点的请求提供跨 spine 的有界分布样本；样本不代表穷尽性总结，也不保证是全书最优排行。

**完整总结：** 对明确命名的章节、当前章、全书或固定附件读取完整目标；其他表述由计划决定。读取完整范围后才开始生成观点清单。按原书顺序将完整语义块分批发送，清单需保留所有显式分论点、限定条件、导言/结语中的有价值观察，例子放在相应论点下，不规定必须三个点。每批清单必须确认覆盖该批全部来源 ID，所有观点只能引用该批实际提供的 ID。

最终回答收到观点清单及其对应的完整本机原文，再合并同义观点、组织主论点与补充观点、分析条件/层次/时期与真正的矛盾。若清单对应的来源未在回答中引用，最多补查改写一次；仍缺失则作为未完成处理。读取覆盖、来源真实性和语义准确是三件事：程序验证前两项的一部分，不能凭有引用就证明观点无遗漏或解释正确。引用核对仍由读者可见的本机原文支持。

引用覆盖按 Markdown 实际链接检查，支持标题、尖括号及引用式写法，代码块和行内代码中的链接不算已引用证据。短范围只有版权等信息、清单无论点时，最终回答仍收到该范围原文以说明情况，不将空清单误报为范围过长。

固定页/选区/阅读段总结复用同一清单流程，但适配器只有该快照，无任何全书入口。固定范围的普通问答保留初版三个本地只读工具 `get_outline`、`search_book`、`read_passage`；名称不扩大权限。其中文问句匹配同时修正。基础调用方的总结初选也完整提供附件，避免只取前五块。

## 模块、边界与预算

- `harness/scope.ts` 区分固定附件与 `book-scope-1` 权限。全书权限仅含文档身份和固定范围标识，`sources` 必须为空，不是全文副本。
- `harness/book.ts` 是格式无关的本机读取接口；`epub.ts` 封装章节、spine、CFI 和原文核验。AI 层不接触阅读 DOM/引擎，UI 不直接使用厂商 SDK。
- `harness/bookConversation.ts` 执行有限计划、读取、清单、汇总与一次缺失引用补查；`retrieval.ts` 提供本地 BM25 倒排索引、中文双字词与分布采样。无持久向量库、网络检索、开放式 Agent 或写入工具。
- 具体问答初选最多 18,000 字符/100 来源。完整总结最多读取 240,000 字符/24 批；通常每批 12,000 字符/100 来源，超出单批目标的完整块可单独发送，但单块最多 20,000 字符。超过预算提前拒绝，不截掉尾部假装完整。
- 清单汇总的原文最多 80,000 字符/1,000 来源，清单序列化最多 80,000 字符。保存格式允许最多 120,000 字符的原文以兼容有界答案数据，实际生成仍受上述更低限制。
- 每任务最多 36 次模型请求（原 24 批外为规划/恢复/补查预留有界额度）；全书具体问答总时限 120 秒，完整总结 8 分钟。每个阶段可取消；即使 transport 不响应 abort，调用方也结束并忽略迟到结果。服务错误、无文本、计划/清单无效、超限和不完整均可见，不静默降级为全书结论。
- 固定范围普通问答仍为三次工具、四次请求、90 秒、去重原文 12,000 字符；直接总结初选可完整提供最多 20,000 字符的附件。页/选区 UI 继续 12,000 字符上限，过长须主动缩小。

## 预算、恢复与缓存

规划预算与清单预算不受用户的回答长度偏好覆盖。规划 4,096 tokens，长度截断重试一次 8,192；清单 16,384，截断仅将失败批次按原块边界二分，最多两层，恢复批次 32,768；一个不可再分的块仍受此次数限制。已校验批次保持可复用，不能把半截 JSON 当作成功清单。

最终回答首试使用用户偏好或默认 8,192 tokens。收到 `finish_reason=length` 时，先保留终止事件中的正文，再用同一证据集续写；没有可见正文时以更高预算重新生成。最多两次恢复，预算按倍数增加且至少 8,192、不超过 65,536，仍受任务总时限约束。只去除确切重复尾部，未知来源继续拦截。恢复期间保留已显示文字，补查失败前不预先清空已有答案；次数耗尽保留部分文本并显示失败，不能保存成已完成。网络/认证/过滤错误不冒充长度不足自动重试。取消和超时覆盖恢复请求。

缓存为按需、本机内存，不增加持久数据库或后台模型任务：

- 每个打开文档由对象身份、文档哈希及解析/索引版本绑定；最多缓存 2,000,000 正文字符/50,000 原文块，超过时本轮读取可用但不保留全书缓存。章节缓存最多 8 项/300,000 正文字符，较旧项先移除。返回副本防止调用方改写缓存原文。
- BM25 索引随已完成的原文缓存复用，首次索引每 32 块让出事件循环并检查取消，spine 读取之间也让出执行。取消不会把未完成全书解析/索引标为可用；独立调用不共用一个可相互取消的未完成请求。
- 观点清单缓存以访问器为所有者，键覆盖文档哈希、范围、问题、原文和锚点、服务/模型配置、自定义提示词及清单版本。仅保存结构与来源校验通过的批次，最多 48 项/500,000 序列化字符；可复用的中间解释仍须由最终原文支持。固定附件访问器独立，不可借缓存读到全书。
- 内存缓存不跨应用重启，文档对象释放后可回收；不写正文、密钥或完整问题到日志。原文预览/跳转以及重发历史的本机验证照常执行。

## 原文引用与历史

模型只接收来源 ID 和本机正文，不接收可信页码/CFI，也不能创建锚点。正文、目录、清单及历史均为不可信阅读数据，其中的指令不能改变权限。服务响应、工具/计划参数和本机记录运行时校验，API 密钥和完整问题/正文不进入日志。

回答中的合法引用按每个回答首次出现顺序本地编号；重复引用沿用编号，未知 ID 不生成可点击入口。悬停/键盘聚焦核验并预览完整本机原文，不翻页；点击再次核验并跳到出处。前后切换只遍历该回答实际引用的来源，保留第一次跳转前的位置。临时 CSS Highlight 不改正文、选区、笔记或文件，关闭/翻页/返回清理；不支持的引擎仍提供原文面板和跳转。

沿用 `glossa-conversations`、`conversation-3` 和每次重新生成的独立版本。每个回答保存 `reading: {scope, sources, mode, coverage?}`：全书 scope 为空正文的权限记录，sources 是最终回答请求实际使用的完整原文；coverage 记录读取策略、目标名和源块数量，不宣称语义完整。固定附件仍严格验证 sources 属于快照。所有范围/版本继续绑定书籍。

全书或总结历史最多四个完整轮次/12,000 字符；只接受同书同范围，重发的原文累计最多 12,000 字符/80 来源且须本机重新核验，整轮放不下则不发送。固定范围普通问答保持原八轮上限。移除/更换附件后，该范围的旧阅读回答不进入新请求；普通旧聊天没有原文依据，不混入书籍事实。恢复旧记录不触发写入迁移或清库。

## 验收与实际质量

用原创 EPUB 和模拟服务验证：默认全书无后台读/模型调用；跨章查找、目录前序言/非线性附注覆盖、命名章节边界、四个明显分论点和结语进入材料/清单、长文本逐批覆盖、缺失引用补查、无效 ID 拦截、附件收窄、不同范围历史隔离、版本保存、取消/超时、预算不足、阶段预算隔离、SSE 终止事件正文保留、有限续写/重试、已完成批次复用、缓存哈希失效与取消、BM25 中文召回，以及来源预览/跳转/高亮/返回和窄栏主题。

工程测试不代替真实模型评估。后续以日常阅读的问题对比遗漏率、原文支持程度、追问连续性和等待时间；不因为模拟服务通过就宣称达到 NotebookLM 的回答质量。支持的初始格式仍是可重排 EPUB。
