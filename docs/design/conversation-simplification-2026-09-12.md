# 对话精简与回答质量方案

日期：2026-09-12。状态：研究建议，尚未实施；不替换现行 PLAN.md。目标是让读者直接提问、快速理解、继续追问并回到原文。

## 建议结论

把日常体验收敛为“一个输入框、一行讨论对象、一段直接回答”。上下文控制仍可查看、调整和移除，但不要求读者先配置材料。优先同时改善界面与回答契约，随后用同一组问题验证材料选择和追问；模型选择最后通过对照评测决定。

本次核对了当前源码、对话设计、测试与已有 420px QA 截图。截图使用模拟回答，只能作为界面依据；未取得用户失败对话和实际模型信息，以下机制问题有代码依据，但尚不能断言哪一项主导了用户的实际失败。

## 界面收敛

常态只呈现：顶部“对话”和新建/更多/关闭；中间消息；底部讨论对象与输入框。目标是读者不展开任何设置就能问第一句并追问。

| 元素 | 建议呈现 |
| --- | --- |
| 讨论对象 | 输入框上方一行，例如“当前页 · 第三章 ▾”；有选区显示“所选文字：…… ×”；保留旧焦点时显示“继续讨论：……”，避免仍标成当前页 |
| 元信息 | 书名、作者、章节、位置继续随请求携带；完整信息放入讨论对象详情，缺失仍标未知 |
| 范围 | 展开后提供“当前页 / 选择书中内容 / 全书检索 / 仅书籍信息”。“选择书中内容”内直接选择原文或目录条目，保留多条目能力；节、篇、章不再成为三种近似配置模式 |
| 材料与成本 | 实际原文、排除操作、用量、预算和追问摘要统一放在详情中；保留发送前核对。低预算下选区放不下时明确提示处理，不能无声舍弃选区 |
| 回答 | 自然短段，来源用句末编号；用轻量文字清楚区分“原文”“推断”“背景”，同类连续段不重复大标题。证据不足直接说明缺什么 |
| 历史及模型 | 放入更多菜单；模型未配置、保存失败等需要行动时就地显示 |
| 后续操作 | 默认保留一个“展开解释”，其余放入更多菜单；自由输入支持“举个例子”“再短点”。按下展开才发新请求，不提前生成长答案 |

移除上下文后，任何依赖该正文的历史也停止外发。翻页不悄悄更换正在讨论的原文；读者点击讨论对象即可“改问当前页”。退出、停止、错误重试、来源跳转和返回仍保留。

## 回答契约：先答中，再按需解释

默认中文回答以 80–180 字、1–2 个短段为起始目标；这是待评测的写作目标，不能为凑字数删掉关键条件。复杂比较可略长，明确要求详细时放宽。英文等语言单独设短答目标，不机械套中文字符数。

- 第一、二句直接解决问题。问词义，先给该处含义；问为什么，先给原因；问区别，先说区别在哪里。
- 后面只补理解该答案必需的理由、原文关系或一个最小例子。例子不能冒充原书案例。
- “再简单点”必须换成更容易理解的表达；“为什么”补缺失的一步；“举例”直接给例子。不要每轮重讲整段。
- 普通问答不用“这是个好问题”“我们可以从三个方面分析”等开场，不自动列学习建议、反问测验或邀请继续。
- 若指代明确就直接回答；只有多个对象会产生不同答案时，问一个具体澄清问题。证据不足时说明缺的材料，并提供对应范围操作。

示例为本方案原创，不是用户书籍内容：

> 原文：一个例子能说明什么，受到它成立条件的限制。
>
> 读者：为什么一个例子不能证明普遍结论？
>
> 目标回答：因为它只说明结论在特定条件下成立；换一组条件，结果可能不同。要推出普遍结论，还需要说明这些条件变化后结论是否仍成立。[1]
>
> 读者：再简单点。
>
> 目标回答：一次成功，只能说明“这一次行得通”，不能证明“每次都行”。（解释性类比）[1]

模型调用仍保留结构化 blocks 与 sourceId 白名单。首轮可先沿用协议，加明确短答要求和少量成对示例；不要先做多次“计划→作答→润色”调用。后续若收紧 schema，应区分新请求与旧记录，避免旧长回答无法打开。

不能用前端截断隐藏长答案来冒充简洁，也不能把输出 token 直接压到很低：JSON 可能被截断，推理模型还可能需要额外预算。先控制可见回答目标，再基于实际服务测量生成预算、首个可见段延迟和长度耗尽率。

## 材料与追问怎么改

保持确定性流程：识别显式选区/继续讨论对象 → 在已授权材料中找依据 → 单次模型调用 → 结构与来源校验。首轮默认当前可见范围；所选文字拥有最高优先级。

1. **区分讨论焦点和可检索范围。** 选区或上一轮对象是焦点；当前页、指定目录条目、全书是授权边界。固定焦点用于省略式追问，不能把“固定这几段”当成“已覆盖这个章节”。
2. **同题追问保留材料；新证据按需补充。** “举例”“再简单点”复用本轮来源。“作者在本章还有其他理由吗”若现有材料不够，提供“在已选章节中查找”；尚未授权章节则先由读者选择。授权过的全书也只发必要证据，不整书上传。
3. **保留真正可用的短记忆。** 第一阶段利用新的短回答保留最近一至两轮完整短摘要、问题与来源绑定，优先保留用户纠正，避免盲截句子。更早内容仍有界压缩。删除材料时按依赖筛除；不能为了连续性恢复已移除正文。需要细粒度摘要时，再引入可验证的逐项来源绑定。
4. **查召回，而不是先加材料。** 对失败问题记录“关键原文是否进入请求”；中文关键词需结合当前讨论对象，减少疑问词干扰；在已授权范围内保留定义、论据、限定条件之间的关系。优先验证现有关键词方案，暂不引入 embedding 或自动代理检索。
5. **完整块超预算要可处理。** 用户主动选择的长段不能无声丢失；提供“改选更短原文”或在详情中提高预算。不要为了凑预算破坏原文锚点。宽泛全书问题仍须说明只拿到部分材料。

## 验证与实施顺序

先建立 20 个小样本，五类各四个：选区词义、论证缺口、省略式追问、切换问题/范围、证据不足。使用原创或明确获准材料；每例写清“必须答出的重点”“支持它的原文”“不应带出的内容”。另取不参与调参的保留题，防止只对样例有效。

每例独立看：关键证据是否选中、前两句是否答中、是否遗漏重要条件、有没有无关扩展、来源是否实际支持、追问是否承接。记录可见字数、首个可见段延迟和总耗时。来源 ID 有效不等于引用支持答案，需要人工核读。

建议起始验收线（尚非实测结果）：20 例中至少 18 例前两句答中；普通短答至少 18 例满足目标长度或有清晰必要例外；省略式追问四例全部承接；来源伪造、越界正文、已移除材料再次外发均为零容忍。小样本只适合迭代，不代表总体质量达到 90%。

实施按三个可交付步骤推进：

1. **短答＋主界面精简。** 保留当前材料能力，合并讨论对象入口，修改提示词与少量范例；验证默认首问、展开、来源、停止和失败状态。
2. **追问＋材料命中。** 用失败样本修复焦点、摘要和检索。保持模型不变，区分只改提示词与再改材料的增益。
3. **模型对照。** 在相同原文、问题和新提示词下对比当前模型与候选模型，再考虑切换；先用固定关键证据判断模型会不会答，再跑端到端检索版本，避免把检索差异误判为模型差异。

真实模型评测未在本轮执行。现有单测与浏览器约定可复用 `conversation.test.ts`、`conversationContext.test.ts`、`conversationPanel.test.tsx` 和 `conversationFlow.browser.test.tsx`；新增实现时补充与来源/追问风险对应的回归。本轮为研究，不需要重新运行产品构建。
