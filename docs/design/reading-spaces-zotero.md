# 阅读空间与 Zotero 只读接入

## 本轮范围

「闲读／学术」是同一书库的两个阅读空间，另提供「全部空间」入口。书籍、完整内容指纹、批注、笔记、阅读位置和删除状态仍只有一份；同一本书可属于两个空间。旧记录缺省显示在闲读，不迁移或重建旧书库，不根据标题猜测学术用途。

侧栏顶端和窄屏书库沿用原生选择框切换空间。本机记住选择，切换时保存各空间当前导航查询并清空选择与剪切状态。书架、列表、最近阅读、书库搜索和最近删除按空间筛选。书籍信息内直接切换归属；批量操作融入已有「移动」菜单，可归入闲读、学术或两个空间，沿用保存失败恢复和撤销。

分组仍为共享目录，空间只过滤其中的书籍及仅含另一空间内容的分支；空分组保留可见。分组重命名、移动和删除是共享结构操作，原有删除确认显示完整成员范围，默认保留文件。需要完全独立目录、同步账号或访问控制时，应另行设计仓库，不能把阅读空间当权限边界。

## 保存与兼容

`Book.readingSpaces` 和独立的 `readingSpacesUpdatedAt` 保存空间归属。合并旧阅读窗口记录时按独立时钟保留空间修改；撤销只恢复本字段，不覆盖新的进度或其他个人编辑。没有有效归属时按闲读兼容读取，不批量改写历史数据。

普通新导入捕获任务开始时的当前空间（全部空间下默认闲读）；重复文件继续复用既有身份，不自动移动既有书籍。Zotero 导入固定加入学术，已存在闲读记录则保留闲读并加入学术。数据库持久提交后发布。当前空间选择和导航记忆是本机偏好；本轮没有新增跨设备空间同步协议。

## Zotero 插件

官方内置 `zotero` 插件沿用插件卡片、三点内部设置、开关及按需加载。学术／全部空间可打开同一入口。打开面板或启用插件不请求数据；主动「连接 Zotero」后才查询本机桌面 Zotero。暂只支持个人文献库、本机可用 PDF／EPUB 附件，集合和条目按每页 100 项读取。

客户端固定访问 `http://127.0.0.1:23119/api/users/0/`，仅提供 GET 集合、条目、子附件及附件本机 URL 的窄接口；拒绝重定向，15 秒请求预算，单响应最多 2 MB，子附件最多 1000 项，超限明确失败。无需云账号、API 密钥或直读 Zotero SQLite。Zotero 本机 API 未启用时显示可操作提示；Glossa 不替用户更改 Zotero 权限。

选择附件后，通过既有完整内容身份导入流程保存阅读副本，强制避免新记录原位导入；不改写 Zotero 文件、书目、集合或标注，不主动上传云端。重复内容复用已有书籍身份；附件内容改变则沿用核心的版本区分规则，不凭 Zotero 条目键、题名或 DOI 合并不同文件。原 Zotero 书目快照独立保存于 `zoteroSource`，不覆盖原文件名或个人改名；离线和停用后仍可查看快照及阅读副本。已有来源快照不随刷新静默替换，后续书目更新需要单独设计。

「在 Zotero 中显示」只允许经过键格式核验的 `zotero://select/library/items/<key>`。应用仅增加该协议的 opener 范围。关闭面板、取消或停用插件终止活动请求；迟到结果不得发布或打开阅读器，重新启用不续跑。已经完成持久提交的阅读副本保留，取消不倒退已提交用户数据。

## 验收记录

自动验证覆盖本机真实 EPUB 文件复制与重导入、个人改名／分组／进度／批注／定位保留、旧窗口合并、空间撤销及保存失败、固定只读请求、路径与响应验证、主动连接、停用取消、迟到响应和失败重试入口。浏览器回归使用隔离书库夹具，不写个人书库。

2026-11-12，经用户单独授权开启 Zotero 10.0.6「允许本机其他应用连接」。使用实际客户端的 GET 接口读到 22 个集合和分页共 136 条顶层条目，取得真实本机附件路径；已核对安装包内 `server_localAPI.js` 的 GET 路由及 `file/view/url` 文本响应协议。该 Zotero 开关允许其他本机应用连接，并非 Glossa 专属授权。

真实 PDF 在临时 Node 书库连续导入两次，仅保留一条身份，隔离批注和阅读定位保留，原附件 SHA-256 不变。该验证因 jsdom 无画布关闭封面生成，仅核验真实文件及数据持久化；不表示原生封面生成或阅读界面通过。个人 Glossa 书库未参与测试，日常安装版未替换。系统 WebView 的原生 HTTP、附件打开全流程及实体触屏仍未验收。证据在 Git 忽略的 `.glossa-dev/qa/reading-spaces-zotero-20261112/`。
