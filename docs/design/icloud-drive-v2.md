# Glossa 的 iCloud Drive 书库

在「设置 → 书库与同步 → iCloud」选择 iCloud Drive 里的专用文件夹。首台设备创建书库，另一台设备选中同一目录，点击「打开 iCloud 书库」。两端分别启用同步。每个目录通过随机标识绑定。遇到两个标识、目录失效或原书身份不符时，客户端保留本机数据并报告问题。

## 保存和恢复

| 阅读动作 | 本机提交 | 对端处理 |
|---|---|---|
| 改书名、移动书籍、增删分组 | 书库 SQLite 同批写入书目和变更记录；分组日志保存在当前目标的设置库 | 按字段合并书目，分组用稳定 ID 表示。离线移动造成循环时可从日志查回原操作 |
| 添加书签、摘录、改笔记 | 逐书 SQLite 在一次事务里更新批注、操作和扩展事件 | 同一正文发生并发编辑，在原批注展开「笔记版本」后可选择或合写；删除与编辑相遇时，正文可从已删除批注恢复 |
| 翻页、回翻、从头重读 | 记录精确定位、设备和阅读轮次。设备时钟与计数共同排序 | 同轮可回翻，各设备位置、历次重读和最远点保留。显著分叉时提示跳转 |
| 改排版 | 全局阅读默认值与逐书覆盖分别记录，字号、边距等按手机、平板和桌面区分 | 只应用允许同步的排版键；窗口位置、目录授权和密钥仅存本机 |
| 阅读计时 | 统计数据库保存不可变区间，其 ID 也是投递幂等键 | 以区间 ID 去重后按原口径汇总 |
| 分享自定义字体 | 字体面板中主动选择字体，选择记录绑定当前书库 | 另一端在字体面板按需下载和校验 |

原书身份沿用完整内容指纹。逐书写入还检查书目 ID 和删除代次。原有逐书 JSON 提供兼容副本，本机事务日志负责恢复已提交的操作。旧目录仍从原位置读取。能核对身份的旧书目、批注及后续差异可重复导入；无法核对的书目在失败明细中列出。旧笔记的原始 CFI、PDF 范围、正文、书签与删除标记均随迁移保留。旧官方云书目须通过已有恢复路径处理。

旧版目录中的续读位置按书目、原书指纹、写入设备、旧时间戳与定位导入。两端读到同一份旧位置会得到同一个快照；重读后才到达的旧位置仍归入最初轮次。

另一台设备永久删除的书目在本机进入可恢复的「最近删除」。本机保留自己的删除记录，待系统确认对应日志段上传后再登记 iCloud 投递成功。

阅读分叉按同一原书、同一轮次识别。两端独立移动后，PDF 相差至少 5 页、EPUB 到达不同正文 spine，或者全书进度相差至少 5 个百分点，就向当前阅读窗口发送一次带目标位置的提示。用户可以留在本页或点击「跳转」。主动「从头重读」创建新轮次，旧设备迟到的进度归入原轮次。

## 目录和增量交换

同步目录位于所选文件夹的 `GlossaSync-v2/<vault UUID>/`。书目、分组、全局排版各有自己的日志流。批注、位置、逐书排版与统计再按书目和完整指纹隔离。书目元数据与缓存、目录授权和路径分开保存。

1. **拉取**时枚举目录，以本机已提交的各作者连续游标跳过旧段。段名包含作者、连续序号和 SHA-256 摘要。缺段、占位文件和未满足的因果依赖留给后续尝试。
2. **合并**时校验书库、文件身份、协议及摘要。在 SQLite 中提交操作和投影。合并同一笔记正文时依据编辑窗口实际看到的父版本；合并删除时保留墓碑。旧段重放保持幂等。
3. **推送**时用固定名称原子发布本机已提交的操作。写入后崩溃可以重发同一段。目录已写入、Apple 报告已上传、另一设备已提交到本地数据库，分别记账。对端在应用后发布包含连续游标的回执，阅读端不会因发送自己的操作而推进对端游标。

原书和字体按 2 MiB 分块。先发布并核对内容块，再发布带完整摘要的清单。PDF 和 EPUB 通过阅读器的随机读取接口按范围取回，其余格式在临时文件完成整书核验后打开。释放托管原书前检查 Apple 对清单和各块的上传状态、云端对象、本机指纹、书库绑定和阅读占用。外部原件及个人批注独立保存。

批注扩展接口 `NoteJournal.eventsAfter(cursor)` 返回稳定事件 ID、批注 ID、事件类型和版本操作。后续经用户授权的每个连接可独立保存游标，按事件 ID 重试。

## 验收范围

协议测试使用独立的磁盘或内存 SQLite 副本，覆盖离线冲突、提交失败、重开、重复投递、乱序和缺段、删除恢复、同轮回翻与重读、字体、文件范围读取与缓存释放。macOS 原生 WebView 测试通过阅读保存入口改写同一条笔记，重开两个本机副本后核对正文、书签和应用回执。另以真实 PDF 和 EPUB 样书验证分块打开、整书下载、再次校验和关闭同步后的本机重开。上传状态在非 iCloud 的隔离目录中应为未确认。

真实设备验收需要在 Mac 与 iPhone 或 iPad 登录同一 Apple 账号并授权同一专用目录。测试应分别记录本机提交、Apple 确认上传、对端看到文件、对端完成应用的时间；同时核对关停后重开、目录授权恢复、已缓存书离线打开及释放后重新取回。本机临时目录的测试时长不能用作双端 iCloud 时延。
