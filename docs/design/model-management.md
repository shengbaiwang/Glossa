# 模型连接、模型与凭据

本轮按 2026-10-30 用户授权实施。先处理凭据访问时机、升级后的授权连续性与测试误切换，再完善模型管理。正式版与 Dev 的身份、书库及钥匙串服务继续隔离。

## 配置与交互

- 连接保存名称、规范化端点及启停状态；连接下保存多个模型及各自的推理档位、输出限制、能力覆盖、收藏和最近选择时间。对话与导图分别选择默认模型。
- 保存、获取模型、测试和设为默认是不同动作。测试使用草稿及本次临时密钥，不写入配置或切换默认值；普通对话测试只报告实际测到的连接能力。
- 模型选择器先显示本机目录、收藏与缓存；获取远端目录由主动刷新触发，失败保留列表和原位重试。服务和模型的低频管理融入既有设置，不增独立管理工作区。
- 活动任务只在真实请求参数变化时取消；改名、收藏或其他用途的默认模型变化不清除导图结果，保存失败后的成果和错误仍可原位重试。
- 兼容接口继续采用 OpenAI chat/completions。显式能力覆盖针对工具、JSON、输出限制参数和推理档位，不以手动标记冒充服务实际支持。能力变化进入导图任务与缓存身份。
- 旧 v1 配置按原连接 ID/端点迁移到 v2，原默认值分别作为两个用途初值；旧配置保留为迁移依据，密钥寻址不因此次配置迁移改变。配置不包含密钥，浏览器密钥只在会话内存。

## 安全存储

- `getSecureItemStatus` 只返回 present/missing/unavailable；元数据不授予密钥读取权限。设置、打开面板和切换模型不为展示状态而读取密钥。
- macOS 查询精确匹配当前用户钥匙串的 service/account，只返回属性并设置 authenticationUIFail；当前记录真正不存在才查询同环境旧服务，正式版才可再查询 Readest 兼容服务，不迁移密钥。清除标记有非敏感状态元数据，避免再次发现旧凭据。锁定、拒绝及不支持查询的环境均为 unavailable，不能冒充不存在。
- 主动发送、刷新和测试仍在安全存储中读取密钥，读取失败明确提示，远端缺密钥在网络前拒绝；临时密钥与保存密钥使用同一校验。地址修改不自动转发旧密钥，HTTPS、本机 HTTP、禁止跳转、日志脱敏及既有来源权限不变。

## macOS 安装身份

- 日常构建不得静默使用 ad-hoc 或在打包后强制覆盖已有正式签名。构建前校验固定签名身份、最终证书、应用 ID 和有效签名。
- 本机自签名身份只作为个人开发使用，私钥留在本机钥匙串，仓库外仅记录公开指纹；不扩大全局信任或既有凭据 ACL。对外分发采用 Developer ID 等适合分发的身份。
- 实测 macOS 对本机自签名代码的钥匙串分区仍绑定 cdhash，仅固定证书不足以解决重复授权。凭据组件固定安装在用户 Application Support/Glossa Signing 中；应用升级不重建或替换该组件。源码或证书变化必须显式升级并重新验收。
- 应用在构建时固定公开证书指纹与组件 cdhash，启动组件前检查文件归属、权限与静态签名，启动后验证运行中子进程签名，验证通过才经 stdin 发送请求。组件验证父进程证书、准确应用标识、运行时加固与 entitlement、UID、PID 与启动时间，并在 stdin 后再次验证；根据已核验身份选择正式或 Dev 服务，请求不能指定任意钥匙串服务。协议与响应有大小限制，访问超时可主动重试，不把密钥放在命令参数、环境变量或日志中。
- 组件分别拥有 `Glossa Credentials v2` 和 `Glossa Dev Credentials v2`。主动使用时按需读取同环境旧 Glossa 服务并复制到新服务，正式版兼容 Readest；旧项保留。拒绝访问不触发其他服务回退，旧清除标记阻止凭据复活。新项由固定组件建立，因此旧应用 ACL 的单次授权也不会成为后续版本重复读取的依赖。
- 本机签名私钥取消长期信任签名工具，构建授权与日常读密钥分开；不能允许其他程序借本机签名工具伪造受信身份。这里只处理本次新建的 Glossa 签名身份，不扩大其他钥匙串条目的访问。
- 连续不同构建的真实合成凭据验收是完成条件，不能用 DR 相同或单元测试代替。
- 旧 ad-hoc 条目首次迁移可能需要用户授权。运行时锁定、权限撤销和凭据删除仍须服从系统保护，不承诺所有场景零弹窗。
